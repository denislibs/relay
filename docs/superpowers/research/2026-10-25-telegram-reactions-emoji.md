# Реакции и анимированные эмодзи в Telegram Web: исследование

Описание поведения Telegram Web K (tweb) и Web A (tt), без кода: оба проекта под GPL,
в Relay переносится только поведение. 1rem = 16px. В конце — что из этого есть в Relay
и чего не хватает.

## 1. Плашки реакций на сообщении

### Внутри или снаружи пузыря

| Сообщение | Где блок реакций |
|---|---|
| Текст, медиа с подписью, документ, аудио, опрос, веб-превью | **Внутри** пузыря, последним ребёнком под текстом |
| Фото/видео без подписи, стикер, большой эмодзи, кружок, сервисное | **Снаружи**, под медиа, без фона пузыря |
| Альбом | В подписи последнего элемента альбома |

Во «внутреннем» режиме элемент времени переносится в конец ряда реакций (`order` последний):
время встаёт в правый нижний угол последнего ряда и делит строку с плашками, а если не
помещается — уходит на свою строку. Когда реакции сняты, время возвращается на место.
В tt то же самое: мета получает `reactions-offset` (float right, `margin-top:-.5rem`, высота 1rem).

«Снаружи»: у исходящих ряд выровнен по правому краю (tt делает `row-reverse`), у входящих по
левому; ширина ряда ограничена шириной медиа (`width:min-content` у обёртки). Сервисные —
по центру, `max-width` 19rem.

### Плашка

| Параметр | tweb | tt |
|---|---|---|
| Высота | 30px (иконка 22 + 8) | 30px |
| Скругление | пилюля 30px | 1.75rem |
| Padding | 0 8px | 0 6px справа, 4px слева |
| Иконка | 22px; `center_icon` рисуется 40px в боксе 22px с `overflow:hidden` (в файле прозрачные поля) | 20px, margin 4px |
| Счётчик | 15px bold, line-height 18, отступ 6px от иконки | semibold, компактный формат (1.2K) |
| Зазоры | 6px между плашками, 6px сверху ряда; обёртка `margin-top:-3px` | gap 6px, `margin-top:.25rem` |
| Hover | `::after` цвета «выбрано» с opacity .08 | фон темнее, 150ms |
| Масштаб при hover | нет | нет |

Цвета (текстовый пузырь): не выбрано — светлый оттенок акцента + счётчик акцентом;
выбрано — заливка акцентом, счётчик белый. У исходящих та же пара на out-палитре.
Снаружи (медиа без подписи): полупрозрачная подложка как у плавающего времени, белый текст;
выбрано у входящих — заливка primary, у исходящих — белая заливка с акцентным текстом.

Анимация выбора (tweb): псевдоэлемент-заливка `scale(0)→1` + opacity 300ms
cubic-bezier(.4,0,.2,1) — пятно вырастает из центра пилюли; одновременно меняются цвет
счётчика и рамки аватаров. Счётчик в tweb меняется без анимации, в tt — посимвольно
(старая цифра уходит вниз с rotateX, новая приходит сверху, 200ms, не более 10 одновременно).

### Аватары вместо счётчика

Если суммарно реакций на сообщении мало (tweb: < 4, tt: ≤ 3) и список реакторов доступен
(личный чат или `can_see_list`; в каналах никогда) — вместо числа стопка аватаров: до 3,
24px, рамка 2px цвета фона плашки (при выборе — цвета заливки), перекрытие −14px, первый
сверху. Иначе — число.

### Порядок и переносы

Порядок с сервера; локально при отправке: по count по убыванию, при равенстве — по индексу в
списке доступных реакций. DOM-узлы переиспользуются по ключу реакции. `flex-wrap`, явного
max-width нет (ширину задаёт пузырь).

### Реакции на отправляемом сообщении недоступны (`pointer-events:none`).

## 2. Быстрая панель над контекстным меню

- Показывается при открытии контекстного меню сообщения, если реагировать можно. Не
  показывается: режим выделения, отправляемые/отложенные/локальные, ПКМ по самой реакции.
- **7 реакций + шеврон** «ещё», если доступных больше (tt: если ровно 8 — все 8 без шеврона).
- Порядок: top-реакции сервера (лимит 75), первой — реакция по умолчанию; в чате с
  ограниченным списком — в порядке списка, но уже стоящие на сообщении — первыми.
- Ячейка 36px (иконка 28 + padding 4). Шеврон 32×32, вторичный цвет.
- Контейнер: высота 40px, скругление 40, `min-width` 56, фон меню + `backdrop-filter:blur(50px)`,
  тень 0 2px 8px rgba(0,0,0,.24).
- Положение: над меню, зазор 8px (`margin-top:-48px`), правый край выступает за меню на 40px;
  хвостик-полукруг 16×8 под панелью справа на 20px. У tt — «облачко мысли»: два пузырька
  (полуовал 16×8 и кружок 8px) под правым краем, на мобильных скрыты.
- Меню расширяется так, чтобы последняя реакция была видна минимум на 65%.
- Запас при позиционировании меню: сверху 44px, справа 40px, слева 56px.
- Появление: панель и пункты меню — два слоя с одним `transform-origin` (угол открытия),
  каждый `scale(.8)→1` + opacity 200ms cubic-bezier(.4,0,.2,1). Панель держится с `opacity:0`,
  пока не отрисованы первые кадры всех 7 анимаций (tt: ждёт 200ms после открытия меню).
- Анимация элементов: сначала `appear` один раз (28px), на последнем кадре подменяется на
  `select`, стоящий на первом кадре; при каждом mouseenter `select` проигрывается один раз.
  Увеличения при hover **нет** ни в tweb, ни в tt. В tt кастомные эмодзи и звезда появляются
  CSS-каскадом `(7 − i) × 20ms` (правые раньше).
- Lite mode / reduced motion: `static_icon` вместо анимаций.
- Прогрев: при наведении заранее грузятся `around` и `center` реакции.
- Клавиатура: стрелки по сетке.

## 3. Полный пикер реакций (по шеврону)

- Контекстное меню закрывается, открывается отдельный dropdown в body.
- Размер 382×420px (tt: 24rem × 22.375rem), скругление 20, тень 0 5px 10px 5px rgba(16,35,47,.14).
- Позиция от прямоугольника быстрой панели: влево 10.5px, вверх 60.5px (tt: −23/−64 плюс
  центрирование относительно панели). Зажим в экран с отступом 8px.
- Анимация `scale(.85)→1` + opacity 200ms, `transform-origin` ≈ 144px/74px — панель
  «разворачивается» в пикер. Мобильные: на всю ширину, по центру, старт scale .5.
- Содержимое сверху вниз:
  1. Строка поиска с рядом иконок групп (сердечки, лайки, дизлайки, праздник, смайлы…).
     Группы приходят с сервера (`getEmojiGroups`), иконки — 24px кастомные эмодзи с
     перекраской в цвет текста, кнопка 28×28, opacity .3 / активная .7, gap 7px, при вводе
     текста ряд скрывается, при прокрутке — градиентная маска слева. Клик по группе
     фильтрует, лупа превращается в стрелку «назад».
  2. Секция без заголовка — первые 16 top-реакций.
  3. «Frequently Used» — недавние (до 32) без дублей с первой секцией, затем остальные.
  4. Наборы кастомных эмодзи (премиум).
- Ячейка 36px (сетка 42px в основном пикере), hover и уже выбранные — фон interactive-hover;
  обычные реакции в сетке **зациклено играют `select`** на общем canvas (низкий приоритет).
- Если список реакций в чате ограничен или достигнут лимит уникальных (`reactions_uniq_max`,
  по умолчанию 11) — пикер «сжимается» до сетки без поиска и наборов.
- Закрытие: выбор, клик вне, Esc. Пока открыт — скролл ленты заблокирован.

## 4. Анимации при реакции

### Какой файл где играет (веб)

| Файл | Использование |
|---|---|
| `static.webp` | Fallback без анимаций; иконка плашки, если нет `center` |
| `center.tgs` | Статичная иконка плашки (кадр 0, 22px); анимированный оверлей при реакции |
| `appear.tgs` | Появление в быстрой панели, один раз |
| `select.tgs` | После appear и на hover в панели; иконка hover-кнопки быстрой реакции (18px); в полном пикере зациклено |
| `around.tgs` | Эффект вокруг иконки при реакции, 80px (tt: 104px) |
| `activate.tgs`, `effect.tgs` | **В вебе не используются** (мобильные клиенты используют `effect` как большой эффект) |

### Когда запускается

- Моя новая реакция (из плашки, панели, пикера, hover-кнопки); на моём сообщении — когда
  count вырос или реакция новая (пришла от другого).
- Непрочитанная чужая реакция на моё сообщение: эффект не при приходе, а когда пузырь попал
  во вьюпорт и реакция прочитана, с задержкой 150ms.
- Только после завершения «тяжёлых» анимаций и если чат открыт; вне вьюпорта не играет.
- Повторный эффект на той же плашке не стартует, пока идёт текущий.

### Как выглядит

- Оверлей `center` 40px (inset −9px) поверх иконки плашки; статичная иконка скрыта
  (`opacity:0`). `around` 80px центрирован по иконке; в tweb рисуется в глобальном
  fixed-контейнере и пересчитывает позицию на скролл (rAF-throttle), удаляется, уйдя за
  экран; в tt — прямо внутри плашки (`overflow:visible`, `z-index` сообщения поднят,
  `contain:layout` на время эффекта).
- Оба плеера создаются с `play:false`, ждут первый кадр, стартуют синхронно; vibrate 100ms.
- По концу `center` оверлей снимается в следующем rAF; `around` удаляется на последнем кадре.
- Зеркалирования по in/out **нет**, `side: center`.
- Generic-фолбэк (tweb), если `around`/`center` ещё не скачаны: случайная анимация из
  `EmojiGenericAnimations` (💥) 100px зеркальная зацикленная + 7 «летящих копий» иконки
  26px по траекториям (tt: CSS `offset-path`, 1.5s ease-out, scale 1→1.25→1, opacity→0).

### Прочее

- Клик по плашке — toggle (своя снимается, чужая ставится). В tt `shouldAddToRecent` только
  из панели/пикера.
- Лимит реакций от одного пользователя: 1 без премиума, 3 с премиумом; порядок в
  `chosen_order`, лишние снимаются с начала.
- Оптимистично: count ±1, я в начало `recent_reactions` (обрезка до 3), при ошибке откат.
- Каналы: опрос реакций видимых сообщений раз в 10s.

## 5. Быстрая реакция без меню

- **Двойной клик** на десктопе в обоих клиентах — **ответ**, не реакция. На touch в tt двойной
  тап (≤200ms) ставит реакцию по умолчанию.
- **tweb, hover-кнопка**: через 400ms после наведения на пузырь (и после первого кадра)
  появляется пилюля 30×26, фон surface, тень меню, выступает за правый край пузыря на 22.5px,
  прижата к низу, внутри `select` быстрой реакции 18px; появление `scale(.8)→1` 200ms
  cubic-bezier(.34,1.56,.64,1) с перелётом, соседние боковые кнопки сдвигаются на 18px.
  Скрывается при открытии меню, оверлея, выделения, уходе с пузыря.
- **tt, quick-кнопка** (не touch): статичная иконка реакции по умолчанию 28px,
  `right:-.875rem; bottom:-.5rem` у пузыря (у своих слева), скрыта (opacity 0, scale .7),
  появляется при приближении курсора ближе 3rem по X и 1rem по Y, transition .2s с
  задержкой .2s. У custom-shape встраивается в мету.

## 6. Кто поставил

- Тултипа при hover по плашке нет ни там, ни там.
- tweb: ПКМ по плашке (личный чат или `can_see_list`) — компактное меню ≤240px: до 6
  человек (аватар, имя, дата), «Показать все», у админа — крестик снять чужую реакцию.
- Попап «Реакции» 400×600: вкладки-пилюли «все (сумма)» + по реакции (иконка 24px),
  список с иконкой реакции справа, пагинация. В tt — то же через пункт контекстного меню
  «N реакций» со стопкой из 3 аватаров, вкладка «все» добавляет просмотревших.

## 7. Анимированные эмодзи в сообщениях

### Когда сообщение — анимированный стикер

- Нет медиа; текст без пробелов целиком состоит из эмодзи; **ровно один** эмодзи (tt допускает
  перевод строки); эмодзи есть в наборе `AnimatedEmojies` (после нормализации: без FE0F,
  тон кожи снимается, если тоны не смешанные). Тон передаётся в lottie как `fitzModifier`
  1–5 (перекраска в воркере), отдельный файл не нужен.
- Рендер: бокс **112×112** (tt 7rem), без пузыря и хвоста, `loop:false` — играет один раз
  при появлении во вьюпорте и замирает на последнем кадре; при повторном появлении
  (tt) играет заново. Слои: thumb → превью webp → canvas, кроссфейд, превью убирается
  через 300ms после загрузки.
- Время — отдельная пилюля в правом нижнем углу (tt: высота 1.125rem, padding 0 5px 0 6px,
  белый текст на `--action-message-bg`; tweb: `bottom:0; inset-inline-end:0` как у стикера).
- Переводы, выделение текста — выключены.

### 2–7 эмодзи

Остаётся текст без пузыря, крупными глифами: 2→90px, 3→84, 4→72, 5→60, 6→48, 7→36,
>7 → 36 (tt: `min(7.5 − .75N, 5.625)rem`, считается максимум из числа строк и эмодзи в
строке). Время — пилюля под эмодзи (`bottom:-1.25rem`). У tweb глобальная настройка
`emoji.big`, при выключении — обычный текст в пузыре.

### Клик по большому эмодзи

1. **Перезапуск** анимации (tt — каждый клик, tweb — если доигралась) и **звук** из
   `animated_emoji_sounds` (tweb: только при повторном клике по доигравшей; tt: каждый клик).
2. **Полноэкранный эффект** — только в личных чатах (оба) и если нет message effect / lite
   mode. Берётся из набора `EmojiAnimations` (цветные сердца → ❤️), первый документ пака
   (разнообразие даёт только случайный сдвиг).
   - tweb: div 360×360 в глобальном оверлее (absolute inset 0, pointer-events none, z 5);
     якорь — rect стикера; для исходящих `x = right − 360`, для входящих `x = left`, плюс
     сдвиг наружу ±16px×(w/200), случайный X ±16, Y ±4; по вертикали центр по стикеру;
     для **входящих** `scaleX(−1)`; не больше 3 одновременно; удаляется на последнем кадре
     или уйдя за экран; позиция пересчитывается на скролл; vibrate 100.
   - tt: стикер 309px в оверлее z 1100, старт в (x,y) левого верха эмодзи ±20px со
     scale 112/309, за 250ms cubic-bezier(.29,.81,.27,.99) к `translate(−50%,−50%) scale(1)`;
     `isReversed` для чужих (`scaleX(−1)`, `translate(100%,−50%)`); на всё время
     `beginHeavyAnimation`; через 3000ms скрывается (opacity 250ms); любое касание/wheel вне
     эмодзи скрывает досрочно.
3. **Синхронизация с собеседником**: клики собираются в пачку 1000ms (t от первого клика в
   секундах) и уходят как typing-action `sendMessageEmojiInteraction {msg_id, emoticon,
   {v:1, a:[{t,i:1}]}}`; получатель, если чат открыт и пузырь виден, симулирует клики с
   задержками t (tt — один эффект на апдейт) и отвечает `emojiInteractionSeen` (у отправителя
   статус «смотрит анимацию»). В tweb непрочитанные входящие и только что отправленные big
   emoji сами запускают эффект при первом появлении во вьюпорте.

### Эмодзи в обычном тексте

Нативный шрифт только на macOS/iOS (tt ещё проверяет поддержку последней версии Unicode),
иначе PNG Apple-набора 18×18 (tt 1.25em, `img-apple-64`, для крупных `img-apple-160`).
Кастомные (премиум) эмодзи — отдельная сущность, в Relay её нет; архитектура «один общий
canvas на блок текста, один плеер на одинаковый docId, компоновщик в воркере, 60fps-тик,
fade-in 250ms, пауза по IntersectionObserver» пригодится, если такое появится.

## 8. Пикер эмодзи (для справки)

Сетка `repeat(auto-fill, 42px)`, ячейка 42, глиф 34 (или PNG 100%); Recent ≤32; категории
лениво через IntersectionObserver; анимированные эмодзи в сетке играют все сразу, пока
категория видна (не по hover); ПКМ/long-press — выбор тона (6 вариантов), сохраняется и
применяется ко всем ячейкам. Строка поиска с иконками групп описана в §3.

## 9. Lottie-инфраструктура (что из неё важно для Relay)

- Воркеров `min(4, hardwareConcurrency)`; один плеер на `(файл, размер)` с refcount — у
  Relay уже так.
- `loop:false` — стоп на последнем кадре, canvas не очищается; onEnded. **У плеера Relay
  колбэка конца нет** — нужен для appear→select и для снятия оверлея.
- Эффекты идут мимо intersector'а (`group:'none'`), но с `forceAlways`/heavy-animation.
- Кэш кадров: < 100px — все кадры; иначе частичный.
- FPS 60 для приоритетных, 30 для мелких/низкоприоритетных.

## 10. Что есть в Relay и чего нет

Есть:
- Данные: одна реакция на пользователя, полный список `{userId, emoji}` в группах и личных
  (можно рисовать аватары), счётчики + `myReaction` в каналах, непрочитанные реакции и FAB,
  настройка набора реакций группы (all/some/none, до 100), право `react`.
- Lottie: tlottie в воркере, пул с refcount, превью первого кадра в Cache Storage,
  `StickerView` с ленивым подключением за 500px, политика автоплея, `restart()`.
- Ассеты на сервере: 74 реакции × 7 файлов + `reactions.json`; `animated_emoji` 599 файлов
  (588 эмодзи), `emoji_animations` 121 (эффекты интеракций), `emoji_generic_animations` 6 (💥),
  `effectemoji` 50 (message effects). Звуков нет.
- Быстрая панель из 6 эмодзи-глифов в шапке контекстного меню.

Нет / расходится:
- Плашки висят **снаружи под пузырём** у всех сообщений (`.rl-reacts` absolute bottom −18px),
  в Telegram у текста — внутри, с временем в ряду. У `MediaBubble`, voice, round, audio, file,
  todo реакции **не отображаются вовсе**.
