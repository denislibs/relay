# Вход в Relay: как это сделано в tweb и что переносим

Дата: 2026-10-18. Источник: `~/Documents/tweb` (HEAD 812502980, новый роутер карточек на Solid). tweb — GPL: берём только поведение, тексты и числа как ориентир. Код, CSS, Lottie/TGS (обезьяна, логотип, «key», «Mailbox», «jolly_roger») не копируем — обезьяну рисуем свою.

## 1. Что сейчас в Relay

- Экран входа — заглушка: имя → `POST /dev/login` → сервер создаёт пользователя (`apps/web/src/ui/Login.tsx`).
- Сеансы уже настоящие: токен в HttpOnly-cookie, хэш в `sessions`, устройство и IP, скользящий срок, завершение сеанса с закрытием сокетов (`apps/server/src/auth.ts`).
- У `users` уже есть уникальный `phone` (`100_profile.sql`), есть `username`, имя/фамилия.
- Нет: кодов, 2FA, QR, паскеев, ограничения попыток. `LoginQR` в ките — декоративный.
- `/dev/login` нужен тестам и Playwright — оставляем за `DEV_LOGIN=1`.

## 2. Флоу tweb (поведение)

Карточки сменяют друг друга по `out-in`: старая уходит в opacity 0 и −24px, новая приходит с +24px; opacity 0.18s, transform 0.2s. Текущая карточка и её данные (`phone_code_hash`, срок повторной отправки) сохраняются — после перезагрузки вход продолжается с того же шага. Карточка 24.5rem, радиус 2rem, по центру экрана; сверху справа — переключатель темы.

| Карточка | Что на ней | Куда дальше |
|---|---|---|
| **Телефон** | логотип 120px, «Вход в Telegram», страна (выпадающий список с флагом и кодом, поиск по названию/ISO/инициалам, автоопределение по ближайшему DC) и телефон с маской по стране и серым «хвостом» шаблона `‒‒‒ ‒‒ ‒‒`; «Далее» со спиннером; ссылки «Вход по QR-коду», «Войти с паскеем» | код / успех / регистрация |
| **QR** (по умолчанию на десктопе) | QR 240px с логотипом в центре, три шага «Откройте Telegram на телефоне → Настройки → Устройства → Подключить → наведите камеру»; ссылки «Вход по номеру», паскей | вход / пароль |
| **Код** | обезьяна 130px (100 на мобильном), заголовок — номер с карандашом «изменить», подпись по способу доставки (в приложении / SMS / звонок / почта); 5 клеток (длина с сервера), невидимый `<input autocomplete=one-time-code>` поверх; автоотправка при заполнении, кнопки нет; таймер «Отправить SMS через 0:59» → ссылка | вход / пароль / регистрация |
| **Пароль (2FA)** | обезьяна закрывает глаза, «Введите пароль», подпись — подсказка пароля, глаз «показать» (обезьяна подглядывает), «Забыли пароль?», «Далее» | вход / восстановление по почте |
| **Регистрация** | аватар 120px, заголовок — живое превью имени, «Имя (обязательно)» до 70, «Фамилия» до 64, «Начать общение» | вход |
| **Восстановление** | 6-значный код из письма, автоотправка, «Отмена» | вход |

Ошибки — без тряски: рамка и подпись поля краснеют, подпись заменяется текстом ошибки («Неверный номер»); у кода — строка под клетками (role=alert), которая раздвигает карточку плавно; у пароля — текст на кнопке «Неверный пароль» до следующего нажатия клавиши. Неверный код очищает клетки и возвращает фокус.

Клетки кода: 3rem, промежуток 0.625rem, активная — рамка основного цвета, мигающий курсор 1.25s; цифра въезжает снизу на 20px, удаляется с уменьшением до 0.5, 0.2s с лёгким перелётом.

## 3. Обезьяна (поведение, которое повторяем своей графикой)

**Следящая (поле кода).** Два состояния: «ожидание» (цикл ~3с, моргает/дышит) и «слежение» (кадр по позиции взгляда).
- Фокус → взгляд на первую клетку.
- Ввод → взгляд на *следующую* клетку: `t = (введено + 1) / длина`. В tweb взгляд упирается примерно в середину кода (кадр зажат) — у нас можно вести до конца.
- Каждый шаг анимируется плавно (~0.5с), назад — быстрее.
- Потеря фокуса → быстро (×7) назад к нулю и переход в «ожидание».
- Полный код — особого кадра нет: ввод блокируется на время проверки, обезьяна возвращается в ожидание; после ошибки — снова фокус.

**С паролем.** Сидит, закрыв глаза лапами. «Показать пароль» → раздвигает пальцы и подглядывает (~0.27с), «скрыть» → закрывает обратно. На ввод не реагирует.

**Наша реализация:** своя обезьяна-SVG с «ригом» вместо Lottie: зрачки и голова двигаются по параметру `gaze ∈ [0,1]`, лапы — по `cover ∈ [0,1]`, пальцы — по `peek ∈ [0,1]`; моргание и дыхание — CSS. Плюсы: нет зависимости и 60-кадровых файлов, взгляд непрерывный (а не по кадрам), тема перекрашивает через токены. Пока рисунок не готов к показу — статичная поза, без мигания.

## 4. Паскеи (WebAuthn) — в tweb есть

- Кнопка «Войти с паскеем» на карточках телефона и QR (не автозаполнение в поле). Появляется плавно, когда сервер отдал параметры (`initPasskeyLogin`); нет поддержки WebAuthn — кнопки нет.
- Клик → `navigator.credentials.get` → `finishPasskeyLogin`. `userHandle` указывает на аккаунт. Ошибки: «Паскей не привязан к аккаунту», отмена — «Что-то пошло не так»; после ошибки — свежий challenge.
- Если на аккаунте облачный пароль — после паскея всё равно карточка пароля.
- Настройки → Конфиденциальность → «Паскеи (N)»: вступление («Защитите аккаунт», «Создать паскей» / «Пропустить»), список «имя · создан · использован», удаление с подтверждением, «+ Создать паскей» до лимита. Создание: `initPasskeyRegistration` → `credentials.create` → `registerPasskey`.

## 5. Что предлагаю для Relay

**Карточки и переходы** — как в tweb: телефон, QR, код, пароль, регистрация, восстановление; `out-in` с ±24px; состояние шага в `sessionStorage` (продолжение после перезагрузки); фокус после окончания входа карточки; переход в приложение — кроссфейд. Это ложится на наш `SlideStack`-подход и правило плавного UI.

**Сервер** (`apps/server/src/domain/login.ts`, миграция `108_login.sql`):

| Шаг | Эндпоинт | Суть |
|---|---|---|
| Код | `POST /auth/send-code {phone}` → `{hash, type, length, timeout, next?}` | код 5 цифр, в базе только хэш; срок 5 мин, 5 попыток |
| | `POST /auth/sign-in {phone, hash, code}` | → сеанс / `password_needed` / `signup_required` |
| | `POST /auth/resend {phone, hash}` | новый hash, следующий способ доставки |
| Регистрация | `POST /auth/sign-up {phone, hash, first, last}` | создаёт пользователя → сеанс |
| Пароль | `GET /auth/password`, `POST /auth/check-password` | см. решение 2 |
| QR | `POST /auth/qr` → `{token, expires}`; ожидание по WS/long-poll | подтверждение с вошедшего устройства |
| Паскей | `POST /auth/passkey/options`, `POST /auth/passkey/finish` | WebAuthn, см. решение 4 |
| Защита | лимиты на номер и IP, растущая пауза → `flood_wait {seconds}` | на карточке — таймер, а не сырой код ошибки |

Вход завершается только через существующий `createSession` — устройство, IP, список сеансов и завершение уже работают.

## 6. Решения, которые нужны от тебя

1. **Куда приходит код.** SMS-шлюза нет.
   - *Предлагаю:* (а) «в приложении» — системный чат «Relay» на всех уже вошедших устройствах (как Telegram); (б) в dev — код в логе сервера и на странице `/dev/codes`; (в) интерфейс для SMS-провайдера на потом. Первое устройство нового номера в проде без SMS не войдёт — нужен провайдер или вход по почте.
2. **Облачный пароль.** *Предлагаю SRP-6a* (как в Telegram: сервер не видит пароль, проверка без передачи пароля; считается на BigInt в воркере). Проще — argon2id на сервере (`Bun.password`) поверх HTTPS.
3. **QR.** Нужен сканер на вошедшем устройстве: Настройки → Устройства → «Подключить устройство» с камерой (`BarcodeDetector`, фолбэк — MIT-декодер). Без мобильного клиента QR полезен только между браузерами. Делать сразу или после кода/пароля/паскея?
4. **Паскеи.** Проверку WebAuthn на сервере — *предлагаю MIT-библиотеку `@simplewebauthn/server`* (проверенная криптография, ES256/RS256/EdDSA). Альтернатива — своя проверка только с `attestation: none` (CBOR + COSE, ~200 строк), как сделали Web Push без зависимостей.
5. **Обезьяна.** Своя SVG-обезьяна с ригом (раздел 3) — подтверди, что именно обезьяна, а не другой персонаж.

## 7. Порядок работ (после решений)

1. Сервер: коды, регистрация, лимиты, тесты; dev-доставка кода.
2. Клиент: карточки телефона (страна + маска), кода, регистрации; переходы; продолжение после перезагрузки.
3. Обезьяна: рисунок, риг, следящая и парольная.
4. Облачный пароль: установка в настройках, проверка при входе, восстановление по почте.
5. Паскеи: вход + раздел в настройках.
6. QR: показ на входе, сканер в «Устройствах».
