# Каналы в Telegram: как это сделано в tweb и telegram-tt

Дата: 2026-10-24. Источники: `~/Documents/tweb` (Web K) и `~/Documents/telegram-dd/reference/telegram-tt` (Web A).
Только поведение и структура экранов, без кода: оба клиента GPL, Relay — clean-room. Это основа для второй части
журнала на чат (`docs/superpowers/specs/2026-10-23-chat-journal-design.md`): каналы, упоминания, «кто прочитал».

## 0. Модель в одном абзаце

Канал в MTProto — тот же тип `channel`, что и супергруппа, с флагом `broadcast` (супергруппа — `megagroup`).
Почти вся логика клиентов ветвится по этому флагу. Полная информация — `channelFull` (счётчики, связанная группа,
закрепы, права просмотра статистики). У каждого канала свой `pts` — это и есть наш журнал чата.

## 1. Создание канала

**Вход.** Плавающая кнопка «карандаш» внизу левой колонки → меню «New Channel / New Group / New Private Chat».

**Шаги.** Оба клиента: название (обязательно), описание (необязательно, 255 символов), фото. Разница в порядке:
- Web K: сначала название/описание/фото → `createChannel{broadcast}` → экран «Add Subscribers» (можно пропустить).
- Web A: мастер общий с группой, `isChannel` переключает режим: сначала «Add Members» (для канала пропускаемый),
  затем название, описание, фото.

**Общее:** фото загружается отдельным вызовом **после** создания; **тип (публичный/приватный, username) при
создании не выбирается** — это настройка потом; после создания сразу открывается чат канала. Ошибка
`CHANNELS_TOO_MUCH` (лимит 500/1000 каналов и супергрупп) показывает список неактивных каналов, из которых
можно выйти прямо из диалога.

**Отличие от группы:** у группы нет описания, название может генерироваться из имён участников, при добавлении в
группу есть чекбокс «показать историю» — у канала его нет.

## 2. Настройки канала

**Кто видит Edit:** админ (любое право) или владелец, и только подписанный.

**Главный экран (Edit / Manage).** Аватар (редактируется при `change_info`), название, описание (255, счётчик),
кнопка «Save» появляется при изменениях. Строки:

| Строка | Кто | Подзаголовок |
|---|---|---|
| Channel Type | только владелец | Public / Private |
| Invite Links | `invite_users` | число ссылок |
| Subscribe Requests | если есть заявки | число |
| Discussion | `change_info` | имя связанной группы или «Add» |
| Reactions | `change_info` | All / N из M / Off |
| Sign Messages (+ «show authors' profiles») | `post_messages` | тумблеры |
| Auto-translation | `change_info`, от уровня буста | тумблер |
| Recent Actions | любой админ | лог действий (в Web A — заглушка) |
| Administrators / Subscribers / Removed Users | админы | счётчики |
| Statistics / Boost | по флагам сервера | — |
| Delete Channel / Leave Channel | владелец / остальные | — |

Чего у канала **нет** по сравнению с группой: экрана «Permissions» (у подписчиков нет настраиваемых прав), «Chat
history for new members» (история всегда видна), «Hide members», топиков, anti-spam.

**Тип канала.** Радио Private / Public. Private: основная ссылка-приглашение, «Revoke». Public: `t.me/` + username с
живой проверкой (3–32 символа, латиница/цифры/`_`, не начинается с цифры, не заканчивается на `_`), лимит
публичных каналов на аккаунт (10/20). Переход public → private предупреждает, что username будет освобождён.
Дополнительно: «Approve new subscribers» (заявки), «Restrict saving content» (запрет пересылки и копирования).

**Discussion (комментарии).** Экран со списком групп-кандидатов (форумы исключаются) и кнопкой «Create New Group»
(создаёт группу «<Канал> Chat» и сразу привязывает). Подтверждение с предупреждениями: приватный канал → «участники
группы увидят сообщения канала»; приватная группа → «подписчики канала увидят сообщения группы»; скрытая история
группы → будет открыта. При привязке клиент сам мигрирует обычную группу в супергруппу и открывает ей историю.
Когда группа привязана — «Unlink Group», а на стороне группы — «Linked Channel» / «Unlink Channel». У группы
появляются настройки «Only subscribers can comment» (`join_to_send`) и «Approve new members».

**Реакции.** У канала: включить/выключить и набор разрешённых; Web A добавляет слайдер «максимум уникальных
реакций на пост» (по умолчанию 11). Режима «все реакции» у канала в Web K нет.

**Админы и права.** Список: владелец первым, у остальных «Promoted by X». Добавление — из подписчиков.
Права **канала**: Change Info · Post Messages · Edit Messages of Others · Delete Messages of Others · Stories
(post/edit/delete) · Manage Live Streams · Add Subscribers · Add New Admins (· Manage Direct Messages). Нет:
Ban Users (в Web A есть), **Pin Messages** (закреп даётся через `post_messages`/`edit_messages`), Remain Anonymous,
Manage Topics, Custom title. Нельзя выдать право, которого нет у тебя. Внизу — «Transfer ownership» (с паролем
2FA) и «Dismiss admin».

**Подписчики.** Список видят **только админы** (в профиле канала нет вкладки участников, онлайн не считается).
Removed Users — с подписью «Removed by X» и «Unblock». Join Requests — Accept all / Dismiss all, бейдж с числом
заявок в шапке чата.

**Статистика.** Пункт в меню «⋮», только если сервер дал `can_view_stats`: рост, подписчики, уведомления,
просмотры по часам и источникам, языки, взаимодействия, реакции, последние посты (просмотры и репосты); по посту —
просмотры, публичные/приватные репосты. **Бусты** — уровень и прогресс, списки бустеров; уровень открывает фичи
(автоперевод, эмодзи-паки, отключение рекламы с 50-го).

**Удаление / выход.** Владелец: «Delete channel» с чекбоксом «для всех подписчиков» (без галки — просто выход).
Остальные: «Leave channel». Доступно из меню шапки, контекстного меню списка и из Edit.

**Меню «⋮» шапки канала:** Mute/Unmute, View discussion, Live Stream, Statistics, Boost, Report, Clear history,
Delete/Leave.

## 3. Посты

- **Кто публикует.** Только админы с `post_messages` (владелец всегда). Плейсхолдер композера — «Broadcast»
  («Silent broadcast» при тихом режиме).
- **Пост ≠ сообщение.** У поста нет `from_id` — автор сам канал. Посты **никогда не «исходящие»**: даже свои
  рисуются слева, без аватаров и имени. Если включены подписи — строка `post_author` (имя админа); при
  «show authors' profiles» — аватар и имя автора как в группе.
- **Мета-строка:** иконка-глаз и просмотры (компактно, 1.2K), в tooltip «Views / Shares», подпись автора, «edited»,
  булавка, время. Справа у пузыря круглая кнопка «Forward» (быстрый репост).
- **Просмотры.** Видимые посты собираются IntersectionObserver'ом, один раз на пост, и раз в секунду уходят одним
  запросом «засчитать просмотр» (до 100 id); ответ приносит свежие `views`, `forwards`, `replies`. Значения только
  растут. Web A сверх того раз в 20 с опрашивает счётчики видимых постов.
- **Тихий пост** (`silent`) — в Web A персистентный тумблер-колокольчик у композера, в Web K пункт меню у кнопки
  Send. **Отложенные** — общий механизм scheduled.
- **Закреп.** В канале право = `post_messages`/`edit_messages`; модалка без чекбокса «уведомить всех» (Web K: закреп
  всегда тихий; Web A: всегда для всех). Лимит закреплённых 50.
- **Правка.** Своё всегда; чужое при `edit_messages`; с этим правом **без ограничения по времени**.
- **Удаление.** Своё или с `delete_messages`; в канале только «для всех», без опций бана.
- **Реакции** на посты без списка реакторов; нет «Seen by»; лимит уникальных реакций на пост.
- **Пересылка.** `fwd_from` = канал + id поста + `post_author`: «Forwarded from <Канал>» с мини-аватаром, стрелка
  «к оригиналу». «Restrict saving content» запрещает пересылку и копирование.
- Реклама (sponsored) показывается только в каналах.

## 4. Комментарии к постам

**Связь.** `channelFull.linked_chat_id` ↔ `linked_chat_id` супергруппы. Каждый пост сервер **автоматически
пересылает в группу**; копия в группе показывается не как «переслано», а как сообщение от канала с бейджем
«channel». Комментарии — ответы на эту копию (`reply_to.top_msg_id` = id копии).

**Поле `replies` на посте:** `comments: true`, `channel_id` (группа), `replies` (число), `recent_repliers`
(до 3 аватаров), `max_id`, `read_max_id` (→ индикатор непрочитанного).

**Кнопка под постом.** Полоса внизу пузыря: до трёх аватаров последних комментаторов (или иконка), текст
«N comments» / «Leave a comment» / «View in chat», стрелка «›», точка непрочитанного (`read_max_id < max_id`). Для
стикеров и кружков — круглая кнопка сбоку. У альбома — одна кнопка на последнем элементе. Для только что
отправленного поста кнопка есть (если у канала есть связанная группа), но неактивна, пока сервер не вернёт `replies`.
В мета-строке поста счётчик ответов не показывается — только кнопка; в группе наоборот («↩ N» и «View N replies»).

**Открытие треда.** `getDiscussionMessage{канал, пост}` → копия в группе, `max_id`, `read_inbox/outbox_max_id`,
`unread_count`; параллельно `getReplies` за первым комментарием. Открывается лента **группы** с `threadId` =
id копии: шапка «N Comments», статичная плашка с исходным постом, сверху копия поста и разделитель «Discussion
started» / «No comments here yet», композер с плейсхолдером «Comment». Пост удалён → тост «Channel post was
deleted». Глубокая ссылка `t.me/<channel>/<post>?comment=<id>` открывает тред с фокусом.

**Кто комментирует.** Права **группы**, не канала. Комментировать можно, не вступая в группу, — если у группы не
включено «Only subscribers can comment» (`join_to_send`; тогда кнопка «Join group») или «Approve new members»
(«Request to join»). Можно писать от имени своего канала (send-as).

**Прочитанность.** Чтение треда — `readDiscussion{группа, копия, read_max_id}`; апдейты
`updateReadChannelDiscussionInbox/Outbox` обновляют `read_max_id` поста и точку на кнопке.

**Счётчики.** Новый комментарий в группе (`updateNewChannelMessage` с `top_msg_id`) увеличивает счётчик треда;
клиент держит связку «тред в группе ↔ пост в канале» и перерисовывает кнопку. Любое сообщение с полем `replies` в
апдейте или ответе обновляет thread info. Web A дополнительно опрашивает `replies` видимых постов раз в 20 с.

**Ответы на мои комментарии** приходят в служебный чат «Replies» (копия ответа с `reply_to{peer, top_msg_id}`);
клик открывает тред с фокусом. Писать в «Replies» нельзя.

**В группе обсуждения:** пункт «View discussion» в меню канала открывает группу целиком; в группе под копией поста
тот же тред.

## 5. Сторона подписчика

- **Превью до вступления.** Публичный канал открывается как обычный чат с историей (polling новых сообщений),
  внизу большая кнопка «Subscribe / Join Channel» («Request to Join» при заявках). Приватная ссылка `t.me/+hash` →
  модалка: фото, название, «N subscribers», описание, аватары участников, кнопка Join / Request.
- **После вступления** — локальное служебное «You joined this channel» (с датой вступления) и карусель «Similar
  channels» под ним. Клиент **не** мутит канал при вступлении: действуют дефолты уведомлений для типа «каналы»
  (отдельная секция в настройках, `InputNotifyBroadcasts`).
- **Нижняя панель** вместо композера: Join → Mute/Unmute (± Direct Messages, Gift).
- **Статус** в шапке и профиле — «N subscribers», онлайн не показывается. В списке чатов у превью нет имени
  отправителя (отправитель — сам канал). В папках каналы фильтруются флагом `broadcasts`.
- **Ограничения:** нет Reply, нет Seen by, нет списка реакторов; есть Forward (если не protected), Copy link
  (`t.me/<username>/<id>` или `t.me/c/<id>/<msg>`), реакции, Report. Галочки «прочитано» у постов не показываются —
  вместо них просмотры.
- **Непрочитанное** — обычный `unread_count` и `read_inbox_max_id`, чтение — `channels.readHistory`. Упоминаний
  в каналах нет.

## 6. Синхронизация

- **Свой `pts` у каждого канала** (`channelStates` / `channelPtsById`), начальное значение из `dialog.pts`,
  `channelFull.pts` и ответов истории. Апдейты без локального pts игнорируются.
- **Дыра** (`pts > local + pts_count`): апдейт в очередь, через 500 мс (`SYNC_DELAY`) — `getChannelDifference
  {pts, limit 1000}`; дубликаты отбрасываются. Нет нужного пользователя/чата в апдейте → тоже difference.
- **`updateChannelTooLong`** → немедленный `getChannelDifference`. **`channelDifferenceTooLong`** → Web K:
  сброс только этого канала (`updateChannelReload`, история заново); Web A: полный `forceSync` всего состояния.
- **Shortpoll** (Web A): до 10 открытых или просматриваемых каналов опрашиваются difference'ом по таймауту сервера
  (по умолчанию 1 с) — сервер не шлёт push по каналам, на которые ты не подписан или которые слишком большие.
- **Апдейты канала:** `updateNewChannelMessage`, `updateEditChannelMessage`, `updateDeleteChannelMessages`,
  `updateChannelMessageViews` (только рост), `updateChannelMessageForwards`, `updateReadChannelInbox/Outbox`,
  `updateReadChannelDiscussionInbox/Outbox`, `updateChannelReadMessagesContents`, `updatePinnedChannelMessages`,
  `updateChannelUserTyping` (с `top_msg_id`), `updateChannelAvailableMessages` (обрезка истории),
  `updateChannel` (смена членства/доступа; пустой `updateChannel` в Web A = полный reset канала, так приходит смена
  связанной группы), `updateChannelParticipant` (Web K инвалидирует участников; Web A не обрабатывает).
- **`channelFull`** кэшируется (Web K: TTL 3 мин): `participants_count`, `admins_count`, `kicked_count`,
  `linked_chat_id`, `pinned_msg_id`, `about`, `exported_invite`, `available_reactions`, `stats_dc`,
  `can_view_stats`, `requests_pending`, `available_min_id`, `read_inbox/outbox_max_id`. Инвалидируется после
  изменений состава, прав и связанной группы.
- ID сообщений канала локальны для канала (клиенты сдвигают их на `MESSAGE_ID_OFFSET`). У нас id глобальные —
  это не нужно.

## 7. Лимиты и значения

| Что | Значение |
|---|---|
| Каналов и супергрупп на аккаунт | 500 / 1000 (premium) |
| Публичных каналов на аккаунт | 10 / 20 |
| Название / описание | 128 (создание) или 255 / 255 |
| Username | 3–32 (новый 5+), латиница, цифры, `_` |
| Закреплённых | 50 |
| Уникальных реакций на пост | 11 по умолчанию |
| Порция участников | 200 |
| Засчёт просмотров | батч раз в 1 с, до 100 id |
| Опрос views/replies видимых постов | 20 с (Web A) |
| Ожидание дыры pts | 500 мс |
| «Seen by» | только группы ≤ 100 участников, 7 дней; к каналам не применяется |

## 8. Что берём для Relay (вторая часть журнала на чат)

**Модель.** `chats.kind = 'channel'`: тот же журнал чата, та же механика, что у групп. Отличия — права
(постят только админы с `post`), нет прав участников, `members` в журнал чата не пишется (вступления не рассылаются;
счётчик подписчиков — из строки чата), подписчиков видят только админы, онлайн не считается.

**Создание.** Название, описание, фото → канал создан → «Добавить подписчиков» (пропускаемо). Тип и username —
потом, в настройках. Лимит каналов на аккаунт — пока не нужен.

**Настройки** (переиспользуем экраны групп, убираем лишнее): название/описание/фото, тип (приватный/публичный +
username + ссылки-приглашения), Discussion (связанная группа), реакции (вкл/выкл + набор), подписи постов, админы
с набором прав канала (Change Info · Post · Edit others · Delete others · Add Subscribers · Add Admins), подписчики
(только админам), удалённые, заявки, удалить/покинуть. Без статистики, бустов, сторис, стримов, автоперевода.

**Посты.** Автор — канал: без аватара и имени, никогда не «исходящий»; подпись `postAuthor` при включённых
подписях; счётчик просмотров (засчёт батчами по видимости, только рост); правка/удаление по правам без лимита
времени; закреп тихий; реакции без списка реакторов; у подписчика нет Reply, вместо композера — «Подписаться» →
«Без звука / Со звуком».

**Комментарии** — самое крупное: связанная группа, авто-копия поста в группу, тред по копии, `replies` на посте
(число, последние комментаторы, `maxId`, `readMaxId`), кнопка под постом с непрочитанным, открытие треда с
плашкой поста, чтение треда отдельно от чата, права комментировать по группе (в том числе без вступления, если не
включено «только подписчики»), «View discussion». Ответы на мои комментарии — личным журналом как упоминание
(у нас нет чата «Replies», заменим событием `mention`/`replyToMe`).

**Синхронизация.** Уже есть: журнал чата, `syncChat`, `chatTooLong` со сбросом одного чата (как Web K, лучше Web A).
Добавить: превью публичного канала до вступления (сервер отдаёт историю и подписывает сокет на `chat:<id>` без
членства — или polling), счётчики просмотров через журнал чата (`views` как событие с коалесцированием) или
опрос раз в 20 с, как в Web A.

**Открытые вопросы для дизайна.**
1. Просмотры: отдельное событие журнала на каждый засчитанный просмотр — лишняя запись на каждого читателя; лучше
   счётчик в `messages.views` с инкрементом батчами и выдачей свежих значений в ответе на засчёт (как Telegram),
   без журнала.
2. Комментарии: держать копию поста в группе (как Telegram) или ссылаться на пост напрямую (тред в группе с
   `postId`)? Копия нужна Telegram из-за раздельных id; у нас id глобальные — можно без копии.
3. Превью канала без членства: подписка сокета на чат без строки в `chat_members`.
