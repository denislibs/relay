# Навигация: стек независимых записей (tweb + telegram-tt) — план

**Цель:** «Назад» (кнопка в интерфейсе, Esc, «Назад» браузера) закрывает ровно тот слой, к которому относится, не трогая остальные. Пример, ради которого всё затевается: «Контакты» → нажали на человека → чат открылся рядом, контакты остались; стрелка «Назад» в контактах закрывает только контакты, чат остаётся.

**Архитектура:** ядро — стек записей с типом, как `appNavigationController` в tweb: каждая запись — открытый слой со своим закрытием (`onBack`), одна запись = одна запись истории браузера. Закрытие из середины — `closeType(type)` (как `back(type)` в tweb). Из telegram-tt — пометка закрытых записей и их ленивая чистка одним `history.go(-n)`, сессионная метка против «мусорных» записей после перезагрузки, замена записи (`replace`) вместо добавления.

## Что сейчас и почему ломается

`nav.ts` хранит на каждую запись истории снимок экрана: путь страницы слева (`stack[i]`) и глубину стека чатов (`layers[i]`). Шаг назад восстанавливает снимок целиком — значит, левая колонка и стек чатов связаны: открыли чат на странице, ушли с неё — закрылся и чат. Esc при этом разбит по 20 местам.

## Модель

```ts
type EntryType = 'page' | 'chat' | 'info';
interface Entry { id: number; type: EntryType; key?: string; onBack: () => void; closed?: boolean }
```

- **push(type, onBack, {key, replace})** → id. Новая запись истории `{ sid, i }` (sid — метка сессии). `replace` или верхняя запись помечена «заменяемой» → `replaceState` вместо `pushState`.
- **close(id)** — слой закрыли сами (кнопка, клик в списке): запись помечается закрытой. Если она верхняя — снимаем её и все закрытые под ней одним `history.go(-n)` (без вызова `onBack`: слой уже закрыт). Если нет — остаётся «дыркой» до момента, когда до неё дойдёт «Назад».
- **closeType(type)** — закрыть последний открытый слой этого типа из любого места стека: вызвать его `onBack`, затем `close`.
- **popstate** (Назад браузера): курсор ушёл на запись `i` — для всех открытых записей выше `i` сверху вниз вызвать `onBack`; если новая верхняя запись закрыта — дочистить закрытые `go(-n)`. Чужая `sid` (запись от прошлой загрузки) — закрыть всё и начать заново. «Вперёд» не поддерживаем — возвращаемся `go(-n)`.
- **Esc** — верхний открытый слой, если Esc не перехвачен (модалка, меню, поле поиска, `escBusy`).
- **Защита несохранённой формы (setLeaveGuard)** — перед закрытием страницы; отказ на popstate — запись возвращается `pushState`.
- `history.state` других модулей не затираем: `#chat=` пишется `replaceState(history.state, …)` — запись сохраняет нашу метку.

## Слои

| Слой | Запись | Открытие | Закрытие из UI | onBack |
|---|---|---|---|---|
| Страница левой колонки | `page`, key = путь | `go(path)` | `back()` — `closeType('page')` | путь → родитель |
| Чат поверх чата | `chat`, key = кадр | `openInner` (push в стек) | стрелка в шапке, клик в списке → `close` | снять кадр со стека |
| Правая панель «Информация» | `info` | `infoOpen: true` | крестик, Esc панели → `close` | `infoOpen: false` |

- Нижний чат (из списка) своей записи не имеет — как сейчас: адрес `#chat=`.
- Модалки, меню, панели поиска остаются со своим Esc (вне истории) — отдельной задачей.
- API страниц (`go`, `back`, `home`, `setLeaveGuard`, `orderFor`, `parentOf`, `pageIndex`) не меняется: сто с лишним вызовов в страницах остаются как есть.
- `back()` на странице без своей записи (пришли по прямой ссылке или после `home`) — подмена пути на родителя без операций с историей, как сейчас.
