# Глобальный поиск как в Telegram Web — план

Цель: поиск в левой колонке работает как в Telegram Web A — отдельный режим со своими вкладками,
недавними чатами и результатами по всем чатам, сгруппированными по месяцам. Код Telegram (GPL) не берём:
только поведение, своими компонентами.

## Как это устроено в Telegram (что переносим)

- **Вход/выход.** Фокус в поле поиска — колонка переключается в режим поиска, «☰» превращается в «←».
  «←», Esc и «Назад» браузера — выход: запрос, вкладка и результаты сбрасываются. Между вкладками
  запрос и уже загруженное сохраняются.
- **Вкладки** (прокручиваются вбок, переход — сдвигом): Чаты, Медиа, Ссылки, Файлы, Музыка, Голосовые.
  Каналов, мини-приложений и публичных постов у нас нет — эти вкладки не делаем.
- **Чаты, пустой запрос:** полоса «частые собеседники» (аватарки) + «Недавние» (до 10 чатов,
  открытых из поиска; крестик «очистить всё»).
- **Чаты, с запросом:** «Чаты и контакты» (локально: чаты по названию + контакты, 5 строк,
  «Показать все») → «Глобальный поиск» (люди по @имени/имени на сервере, от 4 символов) →
  «Сообщения» (по всем чатам, бесконечная прокрутка, подсветка запроса, аватар, имя, дата, автор).
  Пусто во всех секциях — стикер «Ничего не найдено».
- **Медиа / Ссылки / Файлы / Музыка / Голосовые:** по всем чатам сразу, новые сверху, заголовки
  месяцев («Октябрь 2026»), подпись «Вы → чат» / «отправитель → чат», дата: время сегодня, день недели
  на этой неделе, иначе число. Запрос фильтрует и эти вкладки. Медиа без запроса — сетка 3×,
  у видео длительность; клик — просмотр. Ссылка — плитка с буквой сайта, заголовок, адрес, «→ чат»;
  клик — к сообщению. Файл — плитка расширения/миниатюра, размер; клик по дате — к сообщению.
  Музыка — обложка, длительность, исполнитель; клик — плеер, плейлист из результатов.
  Голосовые — аватар отправителя, длительность (голосовые и кружки вместе).
- **Данные:** страницы по 20–40, курсор «до какого сообщения», запросы старого запроса отбрасываются,
  троттлинг ~300 мс, результаты кэшируются по вкладке до смены запроса.

## Что у нас уже есть

- Поиск сообщений по всем чатам: `GET /search?q&chatId&beforeId` (Meilisearch + запасной Postgres,
  доступ перепроверяется в Postgres) → `searchMessages()` в движке; без сети — перебор IndexedDB.
- Общие медиа одного чата: `GET /chats/:id/media?kind=media|file|audio|voice|link&beforeId`
  (`tabWhere` в `domain/chats.ts`) и строки `MediaCell`/`FileRow`/`LinkRow`/`TrackRow` в `SharedMedia.tsx`.
- Вкладки `FolderTabs` + `SlideStack variant="tabs"`, `Highlight`, `snippet`, `ChatRow`, `EmptyState`.
- Нет: режима поиска с вкладками, недавних/частых, кросс-чат медиа, фильтров по типу в индексе,
  заголовков месяцев, поиска людей по имени (кроме `/users/resolve` по точному @имени/номеру).

## План

### 1. Сервер
1. **Медиа по всем чатам:** `GET /search/media?kind=…&q=&before=<id>&limit=40` — тот же `tabWhere`,
   но `chat_id = any(чаты пользователя)`, в ответе к сообщению — `chatTitle` и `chatKind`.
   С запросом: для media/file/audio/voice — по имени файла/подписи/исполнителю (ILIKE + pg_trgm),
   для link — по тексту сообщения. Курсор — id сообщения (как в общих медиа). Индекс
   `(chat_id, id) where attachment is not null` уже есть? — проверить, при нужде добавить.
2. **Поиск людей:** `GET /search/people?q=` — по имени, @имени среди тех, кого можно увидеть
   (контакты, общие чаты) + точное совпадение @имени глобально (как `/users/resolve`), лимит 20.
   Приватность: только поля, разрешённые `publicUser`.
3. **Сообщения:** `/search` возвращает и вложение/форматирование (сейчас движок их теряет) — для
   миниатюры и подсветки в строке.
4. **Частые собеседники:** `GET /search/top` — 10 личных чатов с наибольшим числом сообщений за 30 дней
   (агрегат по messages, кэш на минуту).
5. Тесты: доступ (чужие чаты не попадают), курсор/страницы, фильтр по типу, приватность людей.

### 2. Клиент: данные
1. `apps/web/src/search.ts`: состояние режима поиска (открыт, вкладка, запрос) в global; загрузчики
   по вкладкам с кэшем «запрос+вкладка → страницы», отбрасывание устаревших ответов, троттлинг 300 мс.
2. Недавние: до 10 chatId в localStorage (на устройство, как в Telegram), добавление при открытии
   чата из поиска, «очистить».
3. Офлайн: Чаты (локально по названию) и Сообщения (перебор IndexedDB) работают без сети;
   медиа-вкладки без сети — пометка «нет сети», уже загруженное остаётся.

### 3. Клиент: интерфейс
1. **Режим поиска** в `Sidebar`: фокус → слой поиска поверх списка (сдвигом, как переходы
   в настройках), «☰»→«←» (анимация смены значка), Esc/«←»/«Назад» — выход и сброс.
2. **Вкладки** — `FolderTabs` вверху (липкие), содержимое — `SlideStack variant="tabs"`.
3. **Чаты:** пустой запрос — частые (горизонтальная полоса аватаров) + «Недавние»; с запросом — три
   секции с «Показать все», строка сообщения с аватаром, автором, миниатюрой, подсветкой.
4. **Медиа-вкладки:** вынести `MediaCell`/`FileRow`/`LinkRow`/`TrackRow` из `SharedMedia.tsx`
   в общий модуль (с подписью «→ чат»), заголовки месяцев, бесконечная прокрутка
   (`IntersectionObserver`, как `TabList`), скелетоны с задержкой (без мигания), пустые состояния.
5. Клики: чат — открыть (+ в недавние, поиск закрыть), сообщение — `openInner` с прокруткой
   к сообщению, фото — просмотр с полётом из ячейки, музыка — плеер с плейлистом результатов.

### 4. Проверка
Прогон в браузере (светлая/тёмная, узкая ширина): вход/выход, вкладки, недавние, страницы,
офлайн, плавность (без скачков и мигания). Серверные тесты зелёные.

## Порядок работ (по отдельным коммитам)
1. Сервер: `/search/media` + `/search/people` + `/search/top` + вложения в `/search`, тесты.
2. Режим поиска: вход/выход, вкладки, вкладка «Чаты» (недавние, частые, секции).
3. Медиа-вкладки (общие строки, месяцы, страницы).
4. Полировка анимаций, офлайн, проверка; влить в master.

Работа — в отдельном worktree `relay-search` (ветка `feat/global-search`), master не трогаем до слияния.
