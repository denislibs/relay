# Групповые звонки — план

Цель: голосовые и видеозвонки в группах (как «видеочат» в Telegram): кто угодно из участников начинает звонок,
остальные видят плашку «Идёт звонок · N участников» и присоединяются; сетка видео, подсветка говорящего,
демонстрация экрана, «поднять руку», админ может выключить микрофон. Безопасность — та же планка, что у звонков
1:1 (docs/plans/2026-11-06-relay-calls.md): **сервер Relay и сервер-пересыльщик не слышат и не видят разговор**.

Источник поведения — групповые звонки tweb (`~/Documents/tweb/src/lib/calls/groupCall*.ts`,
`src/components/groupCall/`), GPL: берём только поведение и решения, код не переносим.

## Почему не так, как 1:1

В звонке 1:1 медиа идёт напрямую между двумя браузерами. В группе «каждый каждому» (mesh) не масштабируется: при
N участниках каждый отправляет N−1 видеопотоков, на 4–5 людях кончаются канал и процессор. Поэтому — **SFU**
(Selective Forwarding Unit): каждый отправляет один поток на сервер, сервер раздаёт его остальным, выбирая качество
под каждого получателя. Так делает и Telegram: клиент подключается к одному серверу конференции, участники
приходят списком источников (ssrc), видео — в нескольких качествах (simulcast).

## Выбор SFU

|---|---|---|---|
| **LiveKit** (выбор) | Apache-2.0 | Готовый сервер (один контейнер), браузерная библиотека `livekit-client`: simulcast, выбор качества под размер плитки, говорящий, демонстрация экрана, переподключение, **шифрование кадров на устройстве** (insertable streams) со своим провайдером ключей | Ещё один сервис; их готовые компоненты — React (берём только библиотеку, интерфейс свой) |
| mediasoup | ISC | Библиотека SFU для Node | Низкоуровневый: сигналинг, simulcast-логику, переподключение писать самим; под Bun не проверен |
| Janus | GPL-3 | | Лицензия |
| Jitsi | Apache-2.0 | Готовое приложение целиком | Тяжёлый, свой интерфейс и XMPP |

LiveKit: наш сервер **сам** выдаёт пропуск в комнату — JWT (HMAC-SHA256 общим секретом LiveKit), подписываем на
WebCrypto, без зависимостей. Комната LiveKit = id звонка; в пропуске — право войти только в эту комнату, кто ты
(идентичность = `u<userId>:<session>`), можно ли говорить, срок — минуты.

## Безопасность

SFU видит медиа, если его не зашифровать поверх DTLS. Поэтому — шифрование кадров на устройстве (SFrame-подобное,
`livekit-client` E2EE с **своим провайдером ключей**): SFU пересылает непрозрачные кадры, ключей у него нет.

| Угроза | Ответ |
|---|---|
| SFU / TURN слышит разговор | кадры шифруются на устройстве ключом отправителя (AES-GCM в воркере `livekit-client`), SFU пересылает шифротекст |
| Сервер Relay раздаёт ключи и может подсунуть свой | ключ отправителя каждому получателю — **попарно**, шифром из ECDH эфемерных ключей участников (как в 1:1); общий отпечаток для сверки — эмодзи по всем открытым ключам участников |
| Ушедший участник слушает дальше | при выходе каждый говорящий **меняет** свой ключ и раздаёт новый только оставшимся |
| Новый участник слышит прошлое | при входе ключи тоже меняются: старые кадры новым ключом не расшифровать |
| Чужой входит в комнату LiveKit | пропуск выдаёт только сервер Relay и только участнику группы; срок — 5 минут, идентичность в пропуске — не подделать; комната закрыта для всех без пропуска |
| Выгнанный из группы остаётся в звонке | сервер Relay выкидывает его через API LiveKit (RemoveParticipant) и меняет ключи |
| Спам звонками | начать звонок — право участника (и админское право `calls` в больших группах); лимит частоты |
| Метаданные | SFU знает, кто в комнате и когда говорит (размер пакетов), — неизбежно; держим SFU у себя, без облака LiveKit |

### Ключи (по мотивам 1:1, проще, чем блокчейн Telegram)

1. Входя, участник создаёт эфемерную пару ECDH P-256 и отправляет серверу Relay свой открытый ключ (`groupCallJoin`).
2. Сервер рассылает участникам звонка состав: `{ участник, сессия, открытый ключ }` — кадр `groupCallState`.
3. Каждый, кто говорит (публикует дорожку), создаёт случайный **ключ отправителя** (32 байта) и для каждого
   участника шифрует его: `ECDH(мой, его) → HKDF(соль = id звонка ‖ эпоха) → AES-GCM`. Пакет уходит через сервер
   (`groupCallKeys`), сервер видит только шифротекст.
4. Получатель расшифровывает и кладёт ключ в провайдер `livekit-client` под идентичность отправителя.
5. **Эпоха** растёт при каждом входе и выходе: новые ключи отправителей, старые выбрасываются через пару секунд
   (чтобы не оборвать кадры в пути).
6. **Эмодзи**: SHA-256 от отсортированного списка «участник ‖ открытый ключ» текущей эпохи → 4 эмодзи (та же
   таблица, что в 1:1). Одинаковые у всех — сервер никому не подменил ключ. Меняются при входе/выходе.

Ограничение честно: без постоянных ключей личности сверка возможна только «прямо сейчас» (как и в 1:1), а
одновременно сверять эмодзи вслух в большой группе неудобно — в интерфейсе пишем «сверьте с кем-нибудь из участников».

## Сервер Relay

- **Таблица `group_calls`** (миграция): `id, chat_id, started_by, started_at, ended_at, video, title?` — история и
  длительность; активный — `ended_at is null`, один на группу (уникальный частичный индекс).
- **Состояние в Valkey**: `gcall:<id>` — участники `{ userId, session, pub, muted, video, hand, joinedAt }`, эпоха;
  TTL с продлением по пингам (как `busy:` в 1:1).
- **Кадры** (`packages/protocol/src/groupCalls.ts`):
  - клиент → сервер: `groupCallStart {chatId, video}` → ack `{callId}`; `groupCallJoin {callId, pub, muted, video}` →
    ack `{token, url, iceServers}`; `groupCallLeave`; `groupCallKeys {callId, epoch, to: [{session, data}]}`;
    `groupCallState {muted, video, hand}`; `groupCallMute {callId, userId}` (админ); `groupCallEnd` (админ / начавший);
    `groupCallPing`.
  - сервер → клиент: `groupCallState {callId, epoch, participants}` (только участникам звонка),
    `groupCallKeys {callId, epoch, from, data}` (адресно в `session:<id>`), `groupCallEnded`.
- **Журнал группы**: событие `groupCall {chatId, callId, count, startedAt}` в `chat_updates` — у всех участников
  группы плашка «Идёт звонок · N», без подключения к звонку. Счётчик обновляется не чаще раза в 2 с.
- **Служебные сообщения**: «X начал(а) звонок», «Звонок завершён (12 мин)» — `serviceMessage` типа `group_call`.
- **Права**: новое админское право `calls` («Управлять звонками»: выключать микрофон, завершать для всех); в
  группах до 200 участников начать может любой, в больших — только с правом `calls` (как в Telegram).
- **LiveKit server API** (Twirp, JWT с правом `roomAdmin`): RemoveParticipant (выгнан из группы, вышел по
  таймауту), MutePublishedTrack (админ выключил микрофон — плюс наш кадр, чтобы клиент показал «вас выключил админ»),
  DeleteRoom (звонок завершён). Вебхуки LiveKit (подпись HMAC) — участник отвалился: убрать из состава, сменить эпоху.
- **Конец звонка**: последний вышел или админ завершил; ничей пинг 60 с — задача очереди закрывает.

## Клиент

- `apps/web/src/calls/groupCall.ts` — контроллер: `Room` из `livekit-client` (импорт динамический — библиотека
  ~300 КБ, в основной бандл не входит), свой провайдер ключей (`BaseKeyProvider` с ключом на отправителя), ключи
  (переиспользуем `callCrypto.ts`: ECDH, HKDF, AES-GCM, эмодзи), устройства — из настроек «Звонки».
- Воркер шифрования `livekit-client/e2ee-worker` — отдельный файл сборки (`apps/web/build.ts`).
- Одна вкладка ведёт звонок (Web Lock `relay-call`, общий с 1:1: в группе и личном одновременно нельзя).

**Интерфейс** (по `docs/SMOOTH-UI.md`):
- в шапке группы — кнопка «Начать звонок» (трубка с плюсом); идёт звонок — плашка над шапкой «Идёт звонок ·
  N участников · аватары · Присоединиться» (тот же механизм, что у плашки звонка 1:1 и плеера);
- экран звонка: сетка плиток (1, 2, 4, 6, 9 — дальше страницы), плитка говорящего подсвечена рамкой, у плитки —
  имя, «микрофон выключен», рука; закреплённая плитка на весь экран; демонстрация экрана — большой плиткой;
- справа или снизу — список участников: говорит / молчит / выключен / рука; у админа — «выключить микрофон»,
  «удалить из звонка»;
- кнопки: камера, микрофон, экран, рука, динамик, выйти (у админа — «завершить для всех»);
- свёрнутый звонок — та же плашка над шапкой, что у 1:1, с числом участников;
- служебные сообщения в ленте группы: «X начал(а) звонок» с кнопкой «Присоединиться», пока он идёт.
- Качество: плитки малого размера запрашивают нижний слой simulcast (`setVideoQuality` / adaptive stream), скрытые
  плитки — не подписаны (экономия канала).

## Развёртывание

- Сервис `livekit` (образ `livekit/livekit-server`, фиксированная версия) в `docker-compose.yml`: порт сигналинга
  7880 за нашим nginx (`/livekit/` → wss), медиа — UDP 50000–50100 (или один порт 7882 с мультиплексированием),
  TCP 7881 запасной.
- TURN для LiveKit — наш coturn (те же временные учётки) или встроенный TURN LiveKit; выбрать по замеру.
- Секреты: `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` — у сервера Relay и LiveKit; в `docker-compose.secure.yml`
  обязательны.
- CSP: `connect-src` + `wss://<host>/livekit`; воркер E2EE — `worker-src 'self'`.

## Этапы

1. **Звонок в группе без видео** — LiveKit в compose, пропуски, кадры начала/входа/выхода, состав, журнал группы
   (плашка «Идёт звонок»), служебные сообщения, экран со списком участников и подсветкой говорящего, свёрнутая
   плашка, шифрование кадров с ключами отправителей и сменой эпохи, эмодзи. Тесты сервера (пропуск только
   участнику, эпоха растёт, ключи адресно, выгнанный удалён) и Playwright на трёх браузерах.
2. **Видео и экран** — сетка с simulcast и подпиской по видимости, закреплённая плитка, демонстрация экрана.
3. **Управление** — право `calls`, выключить микрофон / удалить, «поднять руку», завершить для всех, лимиты.
4. **Позже** — запись (только с согласия и с шифрованием — отдельное решение), «слушатели» для больших групп,
   перевод звонка 1:1 в групповой.

## Проверка

- Сервер: пропуск выдаётся только участнику группы и только на эту комнату; срок пропуска; выход и вход меняют
  эпоху; `groupCallKeys` уходит только адресатам; выгнанный из группы получает RemoveParticipant; журнал группы
  несёт счётчик; конец звонка пишет одно служебное сообщение.
- Клиент: `callCrypto` для групповых ключей (пары, эпоха, подмена ключа сервером → разные эмодзи).
- Браузер: три пользователя в Chromium с поддельными устройствами — звук и видео у всех (`getStats`), **SFU не
  может расшифровать**: снимаем поток на сервере (запись LiveKit egress без ключа) — получается шум; выход одного —
  у оставшихся новая эпоха, звук не прерывается; вход нового — он не получает старых ключей.
- Замер плавности сетки при 9 плитках (кадры, длинные задачи) по `docs/SMOOTH-UI.md`.
