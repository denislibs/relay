# «Музыка» в меню вложений и кольцо-визуализатор — как в Telegram Web A

Изучено по исходникам telegram-tt (только поведение; код GPL не берём): `components/modals/musicPicker/*`,
`components/common/PlayingRing.tsx`, `TrackRow.tsx`, `util/audioPlayback/audioAnalyser.ts`,
`global/actions/api/musicPicker.ts`, `config.ts`.

## Как это устроено в Telegram

### Вход
Скрепка → меню вложений → пункт **«Music»** (между «File» и «Poll»). Открывает модалку «Music» (узкая, `slim`,
во всю доступную высоту окна). У запланированных сообщений — то же, но перед отправкой спрашивает дату.

### Модалка
Сверху вниз:
1. **Шапка**: крестик слева, заголовок «Music» по центру.
2. **Поиск** «Search music» (поле-«остров», автофокус на десктопе, крутилка в поле, пока идёт загрузка).
3. **«Select from Files»** — отдельная карточка-кнопка цветом акцента; открывает системный выбор файлов
   только аудио-типов; не аудио — уведомление «файл пропущен»; больше лимита — окно лимита. Выбранный файл
   сразу уходит как музыка (модалка закрывается).
4. Списки «островами» с заголовками:
   - **«Your profile»** (музыка из своего профиля) — с кнопкой «Show more», если не всё загружено;
   - **«Shared Music»** («из чатов») — вся музыка из всех твоих чатов, новые сверху: глобальный поиск
     по сообщениям с пустым запросом и фильтром «аудио», порциями, бесконечная прокрутка.
   - Пусто — «Нет аудио» + пояснение.
5. **Поиск**: с 3 символов (дебаунс 300 мс) вместо списков — «Global search» (у Telegram — через музыкальный
   бот; у нас — по нашим трекам: названия, исполнитель, имя файла). Ничего — «Ничего не найдено по «…»».
   Смена списков — плавное затухание (fade), прокрутка сбрасывается наверх.

### Строка трека
Обложка-кружок 48px с кнопкой play/pause поверх, название, «длительность • исполнитель (или автор)».
- **Клик по строке — отправить этот трек** в чат (тот же файл, без загрузки заново; модалка закрывается).
- **Клик по кругу — прослушать** (не отправляет): играет в общем плеере, плейлист — один трек.
- Enter/Пробел на строке — тоже отправка; строка — `role=button`, фокусируется.

### Кольцо вокруг играющего трека (то, что на скриншоте)
- Появляется у текущего трека (играет или на паузе), плавно проявляется/гаснет (opacity-переход).
- SVG 68×68 поверх обложки 48px (выступает на 10px со всех сторон), цвет — акцент.
- **52 штриха** по кругу (через 360/52 ≈ 6.9°), каждый — радиальная линия от радиуса 26 наружу,
  длина от 0.4 до 6 (толщина 1.25, скруглённые концы).
- **Длина штриха = громкость своей частотной полосы** реального звука:
  - `AnalyserNode` Web Audio (fftSize 2048, сглаживание 0.85), подключён к тому же `<audio>` плеера
    (`createMediaElementSource`, звук дальше идёт в выход как обычно);
  - полосы — логарифмически от 31.5 Гц до 16 кГц, **зеркально**: от верха круга по часовой — низкие → высокие,
    вторая половина круга повторяет первую в обратном порядке (рисунок симметричный);
  - высоким частотам — усиление до ×1.5 (иначе они почти не видны), громкость в степени 1.4;
  - каждый кадр штрих догоняет цель с коэффициентом 0.22 (мягкое движение, без дёрганья).
- **Пауза**: цель = 0, штрихи плавно опадают до точек; когда успокоились — цикл кадров останавливается.
- **Нет анализатора** (iOS, контекст не запущен, недоступен звук): синтетическая «живая» волна —
  сумма двух синусоид по времени и номеру штриха, чтобы кольцо всё равно дышало.
- Если на обложке есть значок «скачать» — у кольца вырез маской (кольцо не наезжает на значок).
- `AudioContext` создаётся/возобновляется при нажатии play (жест пользователя), иначе браузер не даст.

## Что уже есть у нас
- Общий плеер (`player.js`, один `<audio>`), плеер-остров над шапкой, плейлисты, музыка профиля
  (`/users/:id/music`, «добавить в профиль»), отправка аудио (`sendFile kind:'audio'` с обложкой и тегами ID3).
- Поиск музыки по всем чатам: `GET /search/media?kind=audio&q=` (вкладка «Музыка» глобального поиска).
- Меню вложений (`AttachMenu`), модалки (`Modal`), строки `TrackRow` в общих медиа.
- Нет: пункта «Музыка», модалки, отправки уже загруженного трека в другой чат, кольца-визуализатора.

## План

### 1. Сервер
- Отправка существующего трека без новой загрузки — уже есть механизм пересылки: `send` с `forward`
  копирует вложение. Для «музыки из списка» нужен вариант **без заголовка «Переслано»**:
  `forward` с `hideSender: true` (уже поддерживается) — трек уходит как своё сообщение. Доступ к файлу у
  получателя даёт сама новая запись. Для музыки профиля (не сообщение) — `send` с `attachment.id`
  трека профиля: разрешить владельцу трека профиля (сейчас `attachmentForSend` требует владения — свой
  профиль и так мой; чужой — не нужен).
- Ничего нового для «Shared Music»: `/search/media?kind=audio` (уже по всем чатам, страницы, `before`).

### 2. UI-кит
- **`PlayingRing`** (свой компонент, своя реализация): SVG-кольцо из N штрихов, длина по уровням полос,
  мягкое догоняние, пауза — затухание и остановка цикла, синтетическая волна без анализатора,
  `prefers-reduced-motion` — статичное кольцо. Рисование — через `requestMutation`, один rAF на кольцо.
- **Анализатор в `player.js`**: `getAnalyser()` — `AudioContext` + `createMediaElementSource(audio)` +
  `AnalyserNode` при первом play (жест). ⚠ Наши файлы отдаются редиректом на S3 (другой origin:
  `localhost:8333`) — без CORS звук для анализатора «немой» (нули), а с `createMediaElementSource`
  без CORS браузер **глушит сам звук**. Поэтому: `audio.crossOrigin = 'anonymous'` и CORS на бакете
  (Access-Control-Allow-Origin для origin приложения, GET) — проверить на SeaweedFS; если CORS нет —
  не подключать анализатор, работать на синтетической волне.
- **`MusicPicker`** (модалка): шапка, поиск с крутилкой, карточка «Выбрать из файлов», острова
  «Мой профиль» / «Из чатов» / «Результаты поиска», пустые состояния, fade между списками,
  строки с кольцом, клавиатура (Enter/Space — отправить, Tab по строкам).

### 3. Приложение
- Пункт «Музыка» в меню вложений (иконка `music`), открывает модалку для текущего чата.
- Данные: «Мой профиль» — `/users/me/music`; «Из чатов» — `/search/media?kind=audio`, бесконечная прокрутка;
  поиск — тот же эндпоинт с `q` (от 3 символов, дебаунс 300 мс, устаревшие ответы отбрасываются).
- Клик по кругу — `player.play` (плейлист из одного трека); клик по строке — отправка в чат
  (из сообщения — пересылка без отправителя; из профиля — по id вложения), звук отправки, модалка закрывается.
- «Выбрать из файлов» — тот же путь, что отправка музыки сейчас (`sendFile kind:'audio'`, теги ID3, обложка).
- Кольцо — также в плейлисте, музыке профиля и у пузыря музыки в ленте, как у Telegram (`withPlayingRing`).

### 4. Проверка
Модалка: открытие/закрытие, поиск, пустые состояния, бесконечная прокрутка; отправка из каждого списка
и из файлов; кольцо: реагирует на звук, на паузе опадает, синтетика без анализатора, звук не пропадает
(CORS); светлая/тёмная тема, клавиатура, reduced motion.

## Порядок работ (worktree `relay-music-picker`)
1. Анализатор в плеере + CORS бакета (проверить, что звук и спектр работают).
2. `PlayingRing` в ките.
3. Модалка `MusicPicker` + пункт меню + отправка (сервер: отправка трека профиля по id).
4. Кольцо в плейлисте/профиле/пузыре, проверка, слияние в master.
