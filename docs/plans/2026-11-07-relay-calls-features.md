# Звонки: следующие функции — план

Цель: довести звонки 1:1 (docs/plans/2026-11-06-relay-calls.md) и групповые (docs/plans/2026-11-07-relay-group-calls.md)
до уровня, который люди ждут от мессенджера: звонок доходит при закрытой вкладке, есть список звонков, фон можно
размыть, видео не пропадает при уходе на другую вкладку, видно, у кого плохая связь; в группах — звонок из
разговора 1:1, ссылки, запланированные звонки, реакции и чат.

Планка безопасности прежняя: **сервер Relay и пересыльщики (TURN, LiveKit) не слышат и не видят разговор.** Всё новое
либо не касается медиа и ключей, либо шифруется на устройствах теми же ключами звонка.

Источник поведения — tweb и telegram-tt (GPL): берём только поведение, код не переносим. Сторонние библиотеки —
только с разрешительной лицензией (Apache-2.0 / MIT / BSD), файлы моделей — со своего сервера, без CDN.

## Что уже есть и на что опираемся

| Есть | Где |
|---|---|
| Web Push без зависимостей (VAPID, aes128gcm), шлём только тем, у кого нет живого соединения | `apps/server/src/domain/push.ts`, задачи `push.message` / `push.deliver`, `apps/web/src/sw.ts` |
| Звонок 1:1: состояние в Valkey (`call:<id>`, `incoming:<user>`), запрос → `callIncoming` в `user:<id>`, звонок 45 с (`call.ring`) | `apps/server/src/domain/calls.ts` |
| История 1:1 — служебное сообщение `call` (`service_type`, `service_data.call {video, reason, duration}`) | `historyOnly` в `calls.ts` |
| Групповой звонок: LiveKit + шифрование кадров ключом отправителя, эпохи, `mutedByAdmin`, история в `group_calls` и строках `group_call` | `domain/groupCalls.ts`, `apps/web/src/calls/groupCall.ts` |
| Настройки звонков: устройства, **браузерное шумоподавление** (`calls.noise`), АРУ, качество видео, мелодия, громкость | `apps/web/src/prefs.ts`, `ui/settings/Calls.tsx`, `calls/media.ts` |

| Ссылки-приглашения в группы, отложенные задачи с `runAt` | `domain/invites.ts`, `jobs/queue.ts` |

## Этапы (по очереди, каждый — отдельный PR, проверка в Chromium с поддельными устройствами)

### Этап 1. Входящий звонок при закрытой вкладке

**Поведение.** Нет ни одной открытой вкладки Relay → системное уведомление «Анна — входящий звонок» (или «видеозвонок»)
с кнопками «Принять» и «Отклонить», висит, пока звонят. Звонок кончился, а ответа нет — уведомление заменяется на
«Пропущенный звонок от Анны». Вкладка открыта, но скрыта — уведомление показывает сама вкладка (сейчас не показывает),
клик выводит её вперёд на экран входящего.

Сервер:
- `requestCall`: если у адресата нет живого соединения (`onlineUsers`), ставим задачу `push.call` → `push.deliver`
  для каждой его подписки. Полезная нагрузка: `{ kind: 'call', callId, chatId, title, body, video }`, `ttl` = время
  звонка (≈45 с, чтобы опоздавший пуш не звонил через час), `urgency: high`. `deliverPush` получает параметр `ttl`.
- Конец звонка без ответа (`finish` с причиной `missed` / звонящий сбросил) → пуш `{ kind: 'callEnd', callId, missed }`
  тем же подпискам (только если пуш о звонке уходил — флаг в хэше звонка `pushed=1`).
- Пропущенный звонок у пользователя **с** открытыми вкладками: строка в ленте уже есть, ничего не добавляем.
- Текст уважает настройки уведомлений: «скрывать текст» → «Входящий звонок» без имени. Заглушённый чат — звонок всё
  равно приходит (как в Telegram); правило «Кто может мне звонить» уже отсекает чужих до пуша.
- HTTP `POST /calls/:id/decline` (кука сессии, та же проверка Origin, что у остальных POST) — для кнопки «Отклонить»
  из service worker: вкладки может не быть, WebSocket открыть негде.

Клиент:
- `sw.ts`, `push`: `kind: 'call'` → `showNotification(title, { tag: 'call-' + callId, requireInteraction: true,
  actions: [{action:'accept',title:'Принять'},{action:'decline',title:'Отклонить'}], data })`. `callEnd` → закрыть
  уведомление с этим тегом; `missed` → показать «Пропущенный звонок» с тегом чата.
- `notificationclick`: `decline` → `fetch('/calls/<id>/decline', {method:'POST'})`; `accept` или клик по телу →
  фокус существующего окна + `postMessage({type:'call', callId, accept})` или `openWindow('/#call=<id>&accept=1')`.
- Приложение при старте с `#call=` берёт звонок через `callGet` (уже есть), показывает экран входящего и при
  `accept=1` принимает сам — обмен ключами (commit-reveal) идёт как обычно, в уведомлении ключей нет.
- Скрытая вкладка (`document.hidden`) при `callIncoming` показывает то же уведомление через
  `registration.showNotification`; клик → фокус. Без разрешения на уведомления — только звук и заголовок вкладки
  («📞 Анна звонит»).
- iOS (PWA): кнопок в уведомлении нет — клик открывает экран входящего, это нормально.

Тесты: сервер — пуш ставится только офлайн-адресату, `callEnd` после пропуска, `decline` по HTTP завершает звонок,
чужой не может отклонить чужой звонок; клиент — разбор `#call=`. Проверка: Chromium, у адресата закрыты все
вкладки, сервис-воркер жив (persistent context Playwright) → уведомление с кнопками → «Принять» открывает звонок.

### Этап 2. Вкладка «Звонки»

**Поведение.** Пункт «Звонки» в меню левой колонки (рядом с «Контакты»), с числом новых пропущенных. Страница — как
«Контакты» (`rl-sidepage`): список звонков по времени — аватар, имя (или название группы), стрелка входящий /
исходящий, красным — пропущенный и отклонённый, «Видео», длительность, время; кнопка трубки справа — перезвонить тем
же типом звонка. Клик по строке — открыть чат на этом сообщении. Сверху переключатель «Все / Пропущенные».
Удалить из списка = удалить служебное сообщение у себя (уже существующее «удалить у меня»).

Сервер:
- Миграция: частичный индекс `messages (chat_id, id desc) where service_type in ('call','group_call')`.
- `GET /calls?before=<msgId>&missed=1` — служебные сообщения `call` из личных чатов пользователя и `group_call`
  из групп, где он участник, без удалённых у него; страница 50, курсор по `(created_at, id)`.
  Направление: автор сообщения = звонящий (так пишет `historyOnly`) → «исходящий» для автора.
- Счётчик: `settings.calls_seen_at`; число пропущенных = `call` с `reason in ('missed','declined')`, не от меня,
  новее отметки. Отдаётся в снимке и обновляется событием журнала при новом пропущенном; `POST /calls/seen` при
  открытии страницы.

Клиент: `ui/calls/Calls.tsx` (страница), `calls/callsList.ts` (загрузка страницами, слияние с новыми событиями,
сворачивание подряд идущих пропущенных от одного человека в «Анна (3)», как в Telegram), пункт меню с бейджем,
кнопка «перезвонить» через `callBack` из `callUi.ts`.

Тесты: сервер — состав списка, курсор, пропущенные и отметка; клиент — группировка подряд идущих. Проверка: три
звонка разных исходов → список, бейдж, «перезвонить».

### Этап 3. Размытие фона (+ усиленное шумоподавление — по результату)

**Поведение.** В настройках звонков и прямо в звонке (меню у кнопки камеры): «Фон: обычный / размытие». Работает в
1:1 и в групповом. Всё на устройстве: собеседник получает уже размытое видео, сервер ничего не делает.

- `calls/background.ts`: сегментация человека `@mediapipe/tasks-vision` (Apache-2.0), модель
  `selfie_segmenter` (~250 КБ) лежит в `public/models/`, wasm — тоже у нас. Обработка в воркере:
  `MediaStreamTrackProcessor` → маска → размытие фона в WebGL на `OffscreenCanvas` → `MediaStreamTrackGenerator`;
  где их нет (Firefox, Safari) — `<canvas>.captureStream()` в основном потоке с пониженной частотой (15 к/с).
- Включается заменой дорожки: 1:1 — `sender.replaceTrack` (без пересогласования); группа — `LocalVideoTrack.replaceTrack`.
- Бюджет: не дольше 8 мс на кадр на среднем ноутбуке; если дольше трёх секунд подряд — сами снижаем разрешение
  маски, потом подсказка «Размытие тормозит — выключить?».
- Шумоподавление браузера уже есть. Если на проверке с реальным шумом его мало — «Усиленное шумоподавление»:
  RNNoise (`@jitsi/rnnoise-wasm`, Apache-2.0) в `AudioWorklet`. AudioContext здесь создаётся при подключении звонка,
  а не по клику (правило SMOOTH-UI про звуки не нарушается). Решаем после этапа, отдельным флажком.

Тесты: модуль — выбор пути (processor / canvas), выключение возвращает исходную дорожку. Проверка: поддельная камера
с человеком на видео (y4m из ролика), снимок кадра у собеседника с размытием и без.

### Этап 4. Картинка в картинке

**Поведение.** Во время звонка с видео ушёл на другую вкладку или в другое приложение — маленькое плавающее окно с
видео собеседника (в группе — говорящего), кнопками «Микрофон» и «Завершить». Вернулся — окно закрывается.

- Chrome / Edge: Document Picture-in-Picture (`documentPictureInPicture.requestWindow`) — в окне наш небольшой
  компонент (видео + две кнопки), стили копируем в окно. Открывается кнопкой в звонке; **автоматически при уходе с
  вкладки** — через `navigator.mediaSession.setActionHandler('enterpictureinpicture', …)` (Chrome разрешает это
  страницам с активным звонком: камера или микрофон включены).
- Safari / Firefox: обычный `video.requestPictureInPicture()` на видео собеседника, только по кнопке, без кнопок
  управления.
- В окне — тот же `MediaStream`, без новой дорожки; закрытие окна не завершает звонок.

Тесты: выбор механизма по возможностям браузера. Проверка: Chromium, кнопка → окно с видео, кнопка «Микрофон» в окне
выключает микрофон.

### Этап 5. Индикатор плохой связи и подстройка качества

**Поведение.** Плохая связь у меня — плашка на экране звонка «Плохое соединение»; у собеседника — «Слабый сигнал у
Бориса»; в группе — значок на плитке и в списке. Видео само снижает качество, при очень плохой связи — выключается
входящее видео собеседника с подписью «Видео приостановлено из-за слабой связи» (звук важнее).

- 1:1: раз в 2 с `getStats` — потери пакетов, RTT, jitter, `availableOutgoingBitrate` → уровень 0–3 (`calls/quality.ts`,
  чистая функция с гистерезисом, чтобы плашка не мигала). Свой уровень уходит собеседнику по уже существующему
  зашифрованному каналу `state`. Подстройка: `sender.setParameters` — `maxBitrate` и `scaleResolutionDownBy` по уровню;
  настройка «Качество видео» (`auto / saver / high`) задаёт потолок.
- Группа: `ParticipantEvent.ConnectionQualityChanged` LiveKit (у себя и у других) → тот же уровень; `adaptiveStream`
  и `dynacast` уже включены. Для плохой связи — `setVideoQuality(LOW)` / отписка от видео не говорящих.

Тесты: `quality.ts` — пороги и гистерезис. Проверка: `tc`-подобная потеря пакетов через CDP
`Network.emulateNetworkConditions` у одного из участников → плашка у обоих, битрейт упал.

### Этап 6. Групповые: вход без микрофона, звуки, реакции и чат в звонке

**Вход без микрофона.** Переключатель у админа (с правом `calls`) на экране звонка: «Новые участники — без
микрофона». Сервер хранит флаг в `gcall:<id>` (`joinMuted`); при входе не-админа ставит `mutedByAdmin` (механизм уже
есть) — включить микрофон нельзя, можно поднять руку. Флаг виден всем в составе; выключение снимает запрет со всех,
кто не был заглушён лично.

**Звуки.** Вход и выход участника (кроме себя), «вас заглушил админ», «вам разрешили говорить» — `sounds.ts`:
синтез + файлы `/sounds/calls/group_join.mp3` и т. п., как у остальных звуков звонков. В больших звонках (> 10 человек)
звуки входа/выхода молчат.

**Реакции.** Кнопка с несколькими эмодзи на экране звонка; выбранная взлетает над плиткой отправителя у всех на
пару секунд (анимация как у реакций в ленте). **Чат.** Панель «Чат» рядом со списком участников: короткие сообщения
только на время звонка (не сохраняются; кто вошёл позже, прошлого не видит — так и пишем в панели).

Реакции и чат — **без сервера Relay**: через канал данных LiveKit (`publishData`), полезная нагрузка шифруется
ключом отправителя текущей эпохи (AES-GCM, тот же ключ, что у кадров, — через HKDF с другой меткой). Получатели без
ключа (вошли только что) сообщение пропускают. Лимит частоты на клиенте (реакции — 5/с, чат — 1/с, 500 символов).

Тесты: шифрование сообщений канала (свой ключ / чужая эпоха / подделка), сервер — `joinMuted`. Проверка: трое в
звонке, реакция видна у двух других, чат доходит, после выхода участника новые сообщения ему не приходят.

### Этап 7. Запланированный звонок и название

**Поведение** (как в Telegram). Админ с правом `calls`: «Запланировать звонок» в меню группы → название (необязательно)
и время. В ленте: «Анна запланировала звонок «Созвон» на 19:00». Над чатом — плашка «Созвон · сегодня в 19:00 ·
Напомнить» (переключатель «напомнить мне»). В назначенное время всем, кто нажал «Напомнить», — уведомление (и пуш,
если вкладок нет) «Созвон начинается»; админу — «Начать звонок». Звонок не начинается сам: его начинает админ (или
любой, если в группе можно всем); после начала плашка становится обычной «Идёт звонок · Созвон». Название можно
задать и у идущего звонка; оно в заголовке экрана, плашке и строках истории.

Сервер: `group_calls` — колонки `title`, `scheduled_at`, состояние `scheduled` (уникальный индекс «один активный на
группу» учитывает и запланированный); таблица `group_call_reminders (call_id, user_id)`; задача `groupcall.remind`
с `runAt = scheduled_at`; отмена запланированного — админ; запланированный и не начатый через 2 часа после времени —
снимается. `GroupCallSummary` получает `title?`, `scheduledAt?`, `remind?`.

Клиент: модалка (по образцу `ScheduleModal.tsx`), плашка, строки истории в `serviceText.ts`, поле названия в звонке.

Тесты: сервер — планирование, напоминание по задаче, отмена, старт превращает запланированный в идущий. Проверка:
запланировать на +1 мин → уведомление у подписавшихся → старт.

### Этап 8. Звонок без группы: из разговора 1:1 и по ссылке

Один механизм на два пункта: **конференция** — групповой звонок, не привязанный к чату (как «групповые звонки» в
Telegram 2025). Та же LiveKit-комната, те же ключи и эпохи, тот же экран группового звонка.

**Из разговора 1:1.** Кнопка «Добавить участника» в звонке 1:1 → выбор контактов → сервер создаёт конференцию
(участники — двое из звонка), оба клиента подключаются к ней и только потом закрывают прямое соединение (разговор не
прерывается дольше секунды). Приглашённым — входящий звонок «Анна приглашает в звонок (с Борисом)» с «Принять /
Отклонить», включая пуш из этапа 1. Эмодзи меняются (новый состав) — это видно и объяснено подсказкой.

**По ссылке.**
- Конференция: «Пригласить по ссылке» → `https://<домен>/#call=<токен>`; кто открыл — экран «Звонок · Анна, Борис ·
  Войти». Нужен вход в аккаунт Relay.
- Групповой звонок: админ с правом `calls` создаёт ссылку для тех, кто **не** в группе: они попадают только в звонок,
  ленту и участников группы не видят (в звонке — название группы и участники звонка).
- Токен — 128 бит случайных, хранится хэш; ссылку можно отозвать; срок по умолчанию — пока идёт звонок. Вариант
  «вход по одобрению»: вошедший по ссылке ждёт, пока админ / создатель пустит (как заявки в группы).
- Правило «Кто может мне звонить» применяется к приглашениям из этапа 8: того, кто запретил, пригласить нельзя.

Сервер: `group_calls.chat_id` становится необязательным + `kind ('chat'|'conference')`, `group_call_links`
(хэш, кто создал, срок, одобрение); `startConference`, `inviteToCall`, `joinByCallLink`, заявки; права в конференции —
у создателя (заглушить, удалить, завершить). Ключи `gcall:chat:*` — только для звонков в чатах.
У конференции нет чата, поэтому её история не строкой в ленте, а в списке «Звонки» (этап 2): отдельный источник —
`group_calls` с участием пользователя (таблица `group_call_members (call_id, user_id, joined_at)` пишется при входе).

Тесты: сервер — конференция без чата, ссылка (вход, отзыв, срок, одобрение), правило звонков для приглашения,
посторонний по ссылке групповой звонок не видит ленту группы. Проверка: 1:1 → добавить третьего → трое в звонке без
обрыва; ссылка открыта четвёртым пользователем → вход по одобрению.

## Безопасность — что меняется

| Новое | Риск | Ответ |
|---|---|---|
| Пуш о звонке | содержимое уведомления у push-сервиса браузера | полезная нагрузка зашифрована (aes128gcm), ключей звонка в ней нет; «скрывать текст» убирает имя |
| `POST /calls/:id/decline` | отклонить чужой звонок | только адресат этого звонка, проверка Origin / куки как у всех POST |
| Список звонков | утечка чужих звонков | только сообщения из чатов, где пользователь участник, без удалённых у него |
| Размытие / RNNoise | модели и wasm со стороны | файлы у нас, версии закреплены, проверка целостности сборки (`buildIntegrity`) |
| Реакции и чат | сервер читает | шифрование ключом отправителя эпохи; LiveKit видит только шифротекст и размер |
| Ссылки в звонок | ссылка утекла | отзыв, срок, «вход по одобрению», в звонке видно всех; эмодзи меняются при входе |
| Посторонний в групповом звонке по ссылке | доступ к группе | пропуск LiveKit только в комнату звонка, никаких прав на чат |
| Конференция из 1:1 | подмена при переходе | новый состав → новые эмодзи; клиент сверяет, что в составе есть собеседник из 1:1 (тот же открытый ключ сессии) |
