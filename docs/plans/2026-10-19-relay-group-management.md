# Управление группой (как в Telegram) — план

**Цель:** владелец и админы управляют группой, как в Telegram Web A: информация, тип (публичная/частная), права участников и исключения, админы с правами и званиями, участники, удалённые, ссылки-приглашения, заявки, реакции, история для новых, передача владения, выход и удаление. Сервер — единственный источник правды и проверяет каждое право.

**Происхождение:** поведение разобрано по telegram-tt (GPL) — только как описание; код пишем сами (clean-room). Без кода и графики Telegram.

**Ветка:** `feat/groups` (worktree `~/Documents/relay-groups`), master параллельно меняют другие сессии.

## Что уже есть

- `chats(kind, title)`, `chat_members(role default 'member', last_read_id, joined_at)` — role никто не читает.
- `createGroup` + служебное `group_created` (тип в `messages.service_type`); владелец выводится из автора `group_created`.
- `GET /chats/:id/members` (`presence.chatMembers`) — список без ролей; кэш на клиенте (`members.ts`) не инвалидируется.
- Правая панель `Info.tsx` со своим `SlideStack` (`info`, `edit`); служебные сообщения в ленте — ветка `rl-action` (`Feed.tsx`).
- 2FA-пароль (SRP) — `password.ts`: передача владения требует его, как в Telegram.

## Модель данных — миграция `124_groups.sql`

`chats` (только для `kind = 'group'`):

| колонка | смысл |
|---|---|
| `about text` | описание, до 255 символов |
| `photo jsonb` | `{id, small, thumb, at}` — как у профиля |
| `owner_id bigint` | владелец (заполняется из `group_created` для старых групп) |
| `rights jsonb` | права участников по умолчанию — **разрешённое** (`MemberRights`) |
| `slow_mode int default 0` | секунды: 0, 10, 30, 60, 300, 900, 3600 |
| `history_hidden bool default false` | новые участники не видят историю до вступления |
| `join_approval bool default false` | вступление по ссылке/юзернейму — через заявку |
| `username text` | публичная ссылка; общее пространство имён с `users.username` |
| `reactions jsonb` | `{mode: 'all'|'some'|'none', allowed: string[]}` |
| `protected bool default false` | запрет пересылки и сохранения |

`chat_members`: `admin_rights jsonb` (null — не админ), `rank text` (≤16), `promoted_by bigint`, `restricted jsonb` (исключение: разрешённое для этого участника, null — как у всех), `inviter_id bigint`, `history_from bigint default 0` (первое видимое сообщение). `role`: `'owner' | 'admin' | 'member'`.

Новые таблицы:
- `chat_bans(chat_id, user_id, banned_by, at)` — «Удалённые»: не вернуться по ссылке, пока не разбанят.
- `chat_invites(id, chat_id, token unique, creator_id, title, expires_at, usage_limit, usage, approval, revoked, primary_link, created_at)`.
- `chat_invite_joins(invite_id, user_id, at, via_request)`.
- `chat_join_requests(chat_id, user_id, invite_id, at)` primary key `(chat_id, user_id)`.
- `chat_photos(id, chat_id, big, small, thumb, at)` — фото группы видны всем (как превью ссылки: показываются в приглашении).
- `messages.service_data jsonb` — участники события `{users: [{id, name}], title?}` (имена на момент события).

## Права

`MemberRights` (разрешено участникам): `text`, `photos`, `videos`, `files`, `music`, `voice`, `round`, `links` (превью), `react`, `invite`, `pin`, `info`.
«Медиа» — производное: разрешено, если разрешён хоть один медиа-пункт; переключение «Медиа» ставит все медиа-пункты. `links` нельзя без `text` (как в Telegram).

`AdminRights`: `info`, `delete`, `ban`, `invite`, `pin`, `addAdmins`. Владелец — все права неявно.

Проверка (`domain/groupRights.ts`, одна функция `can(member, chat, right)`):
- владелец — всё; админ — по `admin_rights` (админ также не ограничен правами участников и медленным режимом);
- участник — `restricted ?? chat.rights`, и исключение не шире умолчаний;
- `sendMessage` по `kind` (+ `links`: без права превью не строится), медленный режим, `react` + режим реакций, `pin`, удаление чужих (`delete`), правка инфо (`info`), добавление (`invite`), бан (`ban`), назначение админов (`addAdmins`; правит только назначенных собой, владелец — всех; нельзя дать право, которого нет у себя).
- приватность `groupInvite` («Кто может добавлять меня в группы»): нельзя добавить — в ответе список, клиент предлагает отправить ссылку.

## Протокол

`ServiceType` += `title_changed`, `photo_changed`, `photo_removed`, `members_added`, `member_left`, `member_removed`, `joined_by_link`, `joined_by_request`, `owner_changed`, `protected_on`, `protected_off`. `Message.service` += `data?`.

`Update` +=
- `groupUpdated {chatId, group: GroupInfo}` — всем участникам: инфо, права по умолчанию, медленный режим, тип, реакции, число участников.
- `membership {chatId, me: MyMembership}` — только этому человеку: роль, права админа, исключение, звание.
- `membersChanged {chatId}` — всем: перечитать список участников (клиентский кэш `members.ts`).
- `chatRemoved {chatId}` — удалили/вышел/группу удалили: движок убирает чат, сообщения и строки IndexedDB.

`ChatSummary` += `group?: GroupInfo`, `me?: MyMembership` — первый снимок и `tooLong` приносят то же.

## HTTP (все — `/groups/:id/...`, проверка прав на сервере)

| метод и путь | что |
|---|---|
| `PATCH /groups/:id` | `{title?, about?}` |
| `PUT/DELETE /groups/:id/photo` | фото (то же, что у профиля: 640 + 160 + thumb) |
| `PUT /groups/:id/rights` | права по умолчанию + `slowMode` |
| `PUT /groups/:id/settings` | `historyHidden`, `joinApproval`, `protected`, `reactions` |
| `PUT /groups/:id/username` · `GET /groups/username/check` | публичная/частная |
| `GET /groups/:id/members?filter=all|admins|restricted|banned&q=` | участники с ролями |
| `POST /groups/:id/members` | добавить `{userIds}` → `{added, privacyRestricted}` |
| `DELETE /groups/:id/members/:uid` | удалить (бан) / выйти (сам) |
| `PUT /groups/:id/members/:uid/restrict` | исключение (null — снять) |
| `DELETE /groups/:id/bans/:uid` | разбанить |
| `PUT /groups/:id/admins/:uid` | `{rights, rank}`; `rights: null` — снять |
| `PUT /groups/:id/rank` | своё звание (если разрешено) |
| `POST /groups/:id/owner` | передать владение `{userId, proof}` (SRP-пароль) |
| `DELETE /groups/:id` | удалить группу для всех (владелец) |
| `GET/POST /groups/:id/invites`, `PATCH/DELETE /groups/:id/invites/:inv`, `POST .../primary/revoke`, `DELETE .../invites?revoked=1` | ссылки |
| `GET /groups/:id/invites/:inv/joined` | кто вступил, заявки по ссылке |
| `GET /groups/:id/requests`, `POST .../requests/:uid {approve}`, `POST .../requests {approve}` (все) | заявки |
| `GET /join/:token` · `POST /join/:token` | превью приглашения и вступление (или заявка) |
| `GET /join/@:username` · `POST /join/@:username` | публичная группа |

Ссылка-приглашение: `${origin}/+TOKEN`; публичная: `${origin}/@username` (клиент разбирает путь при старте).

## Движок

- `LocalChat` += `group?`, `me?`, `membersRev` (растёт на `membersChanged` — сигнал перечитать участников).
- `applyUpdate`: `groupUpdated`, `membership`, `membersChanged`, `chatRemoved` (новый путь удаления из store и IDB).
- Действия: всё управление — HTTP-вызовы через `engine.call({type:'group', op, chatId, body})` с оптимистичным применением там, где ответ — новое состояние.
- `chatItem()` отдаёт `group`, `me`, `membersRev`.
- История при `history_hidden`: сервер просто не отдаёт сообщения до `history_from` (история, медиа, поиск, «к дате», цитаты, последнее сообщение в списке).

## Клиент

Правая панель «Информация» → карандаш «Изменить» у группы (если есть хоть одно право админа или владелец). Стек экранов (`ui/group/*`):

1. **Изменить группу** — фото, название, описание (255, счётчик); строки: Тип группы (владелец), Разрешения `N/12`, Реакции, Администраторы, Ссылки-приглашения, Заявки (если есть), Участники; «История чата для новых участников»; «Удалить и покинуть группу». Сохранение — круглая кнопка-галочка, появляется при изменениях.
2. **Тип группы** — частная/публичная, юзернейм с проверкой, основная ссылка (скопировать, сбросить), «Одобрять новых участников», «Запретить копирование».
3. **Разрешения** — чекбоксы (Медиа раскрывается на 7 пунктов, счётчик x/7), медленный режим (шкала), «Удалённые пользователи», «Исключения» (+ добавить).
4. **Исключение участника** — те же чекбоксы, недоступное по умолчанию — выключено и заблокировано; «Удалить из группы».
5. **Удалённые** — список «удалил(а) X», «Разблокировать»; «+» — удалить участника.
6. **Администраторы** — владелец первым, «назначил(а) X»; «+» — выбор участника.
7. **Права администратора** — шапка с человеком, чекбоксы прав, звание (16), «Снять с должности», «Передать права на группу» (владелец; пароль 2FA).
8. **Участники** — поиск, роли и звания справа, контекстное меню «Удалить», «Изменить звание»; «+» — добавить (контакты + поиск), кому нельзя — «Отправить приглашение».
9. **Ссылки** — основная (копировать/поделиться/сбросить), «Создать ссылку», дополнительные с подписями (осталось/вступили/истекает/заявки), отозванные, «Удалить все отозванные».
10. **Ссылка (создать/изменить)** — одобрение, название, срок (час/день/неделя/без/свой), лимит (1/10/100/без/свой).
11. **Ссылка — кто вступил** — люди и заявки по ссылке.
12. **Заявки** — принять/отклонить, «Принять всех»/«Отклонить всех»; плашка заявок в шапке чата.
13. **Реакции** — все/некоторые/нет, выбор эмодзи.

Плюс: экран вступления по ссылке (превью группы → «Вступить» / «Подать заявку»), композер в ограниченной группе («Отправка сообщений запрещена», медленный режим с отсчётом, вложения только разрешённых видов), служебные сообщения в ленте и списке чатов, выход из группы (если владелец — сначала передать владение или удалить), запрет пересылки при `protected`.

## Этапы (каждый — свой коммит, тесты зелёные)

1. Миграция + протокол + `groupRights.ts` + доменные операции и маршруты + серверные тесты (права, баны, ссылки, заявки, история, медленный режим, передача владения).
2. Движок: поля, события, `chatRemoved`, действия + тесты движка.
3. UI: стек экранов «Изменить группу», служебные сообщения, композер, вступление по ссылке.
4. Проверка в браузере двумя-тремя пользователями (Playwright/DevTools), strict-dom, плавность.

## Чего не делаем

Темы (форумы), связанный канал, платные сообщения, guard-боты, журнал действий («Недавние действия» — в Web A выключен), скрытие списка участников, анонимные админы — в Relay нет каналов/ботов, к которым это относится.
