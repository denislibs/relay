# Личный канал в профиле и поиск по настройкам — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** две независимые фичи. (1) Пользователь выбирает свой публичный канал, и тот показывается в его профиле с последним постом. (2) В настройках есть поиск по всем пунктам с переходом сразу к нужной строке и её подсветкой.

**Архитектура:** фичи не пересекаются по файлам, кроме `Main.tsx` (своя карточка профиля) — их можно делать двумя параллельными ветками, по PR на часть. Личный канал: одно поле в профиле (`users.personal_channel_id`), едет существующим `userUpdated`; сам пост грузится при открытии профиля через уже готовый `GET /groups/:id` (`channelPreview`). Поиск: ручной индекс пунктов настроек + чистый модуль сопоставления + слой поиска на странице `settings`; строки страниц помечаются `data-setting`.

**Стек:** Bun + Postgres (сервер), движок в SharedWorker, Preact, кит `packages/relay-ui`.

## Global Constraints

- Плавный UI прежде всего (`docs/SMOOTH-UI.md`, память relay-smooth-ui): поздние данные — через `Expand`, лоадеры с задержкой и минимальным временем, кроссфейды, без вспышек пустоты.
- Дисциплина фаз: чтения раскладки — в `requestMeasure`, записи — в `requestMutation`. Строгий DOM в dev — 0 нарушений.
- Правила стека (`docs/navigation-rules.md`): канал из профиля открывается поверх (`openChannel(id, 'inner')`).
- Никакого кода telegram-tt и tweb (GPL): только поведение, своя реализация.
- Иконки — из VK Icons через `build_vk.py`, не из Telegram и не из MAX.
- Проверка только в Chrome (chrome-devtools MCP / Playwright, 127.0.0.1), не во встроенном браузере Claude.
- Тесты: сервер `docker compose --profile test run --rm test`, движок `... test-engine`, веб `cd apps/web && bun test`, кит `cd packages/relay-ui && bun test`.

## Что взято из анализа

**Личный канал (telegram-tt, tweb).**
- Где: последний блок «Изменить профиль», отдельная карточка с оранжевой плиткой-мегафоном: «Личный канал / Добавить канал» и подпись снизу «Покажите в профиле канал, которым вы управляете».
- Выбранный канал рисуется как ячейка списка чатов (аватар, название, последний пост, время), без бейджей и «печатает»; клик снова открывает выбор.
- Выбор — модалка «Выберите канал» с поиском по названию и @username; если канал уже выбран — красная «Убрать канал» внизу. Нет подходящих каналов — тост вместо модалки.
- Подходящие каналы отбирает сервер: только **публичные** каналы, которыми пользователь управляет.
- Сохраняется вместе с остальным профилем по ✓ (ничего не уходит до сохранения).
- В чужом профиле: строка «Канал · N подписчиков» и под ней та же ячейка с последним постом; клик открывает канал **на этом посте** (скролл + подсветка). Нет канала у сервера — блока нет.
- Telegram не шлёт отдельного обновления: профиль перезапрашивается. У нас есть журнал — поле едет `userUpdated`.

**Поиск по настройкам (только tweb; в telegram-tt его нет).**
- Лупа в шапке настроек → поиск заменяет шапку и содержимое той же страницы (быстрый кроссфейд), фокус сразу в поле.
- Пустой запрос — «Недавние» (до 5 последних выбранных). Порядок не прыгает, пока список на экране.
- Строка результата: заголовок пункта, подзаголовок — путь через « › » без корня «Настройки»; плитка раздела только у первой строки группы. Группы — по разделу верхнего уровня.
- Сопоставление: нормализация (регистр, пунктуация, у нас ещё ё→е), второй вариант запроса в другой раскладке (qwerty↔йцукен), каждое слово запроса — префикс какого-то слова пункта (AND), без fuzzy. Синонимы на пункт.
- Ранжирование: начало заголовка → подстрока в заголовке → только синонимы; раздел выше пунктов; меньшая глубина выше; алфавит.
- Переход сразу на целевую страницу (без промежуточных), «назад» возвращает к результатам с тем же запросом; строка прокручивается в центр и вспыхивает (≈1,6 с, фон акцента 16 %), без анимаций — без вспышки; поздняя строка ждётся до 3 с.
- Индекс в tweb генерируется из AST (360 пунктов) — у нас страницы на JSX без реестра, поэтому индекс ручной (~150 пунктов) с тестами на целостность. FAQ и сервер не ищутся.

# Часть 1. Личный канал

## Решения

- **Кто может:** только **владелец** публичного канала (не админ): иначе админ может выставить в профиль чужой канал. Расширить на админов с правом `info` — одной строкой в запросе, если захотите.
- **Что хранится:** `users.personal_channel_id bigint null references chats(id) on delete set null`.
- **Что видят другие:** `PublicUser.personalChannel?: { id, title, username, photo, members }` — снимок для мгновенной отрисовки строки; **последний пост в `userUpdated` не возим** (иначе каждый пост в канале рассылался бы всем зрителям владельца). Пост берётся при открытии профиля из `GET /groups/:id` (`last`) и кэшируется движком.
- **Когда сбрасывается сам:** канал удалён, стал приватным (снят username), владелец сменился. Сервер обнуляет поле в той же транзакции и шлёт исправляющий `userUpdated` (`republishUser`).
- **Кому видно:** тем же, кто видит профиль (`viewersOf`/`canView`). Зрителю, забаненному в канале, `GET /groups/:id` откажет — блок не показываем (снимок без поста не рисуем).
- **Порядок в профиле:** блок над `PeerRows` (как в Telegram — перед телефоном/именем пользователя), и в своей карточке на `settings`.

# Часть 2. Поиск по настройкам

## Решения

- **Индекс — ручной** (`apps/web/src/settingsSearch/entries.ts`): у нас нет реестра страниц, а генератор по AST для ~150 пунктов дороже, чем список с тестами. Пункт: `{ id, path, title, keywords?, kind: 'section' | 'row' | 'toggle' | 'option' | 'subsection', when? }`. Раздел (`section`) — это сама страница из `PAGES`. `when(ctx)` прячет недоступное (раздел разработчика без dev-режима, «Отключить пароль» без пароля).
- **Тексты** живут в индексе на русском (у нас нет языковых пакетов); синонимы — там же (`keywords: ['тёмная тема', 'ночной режим']`).
- **Якоря:** строки на страницах получают `data-setting="<id>"`. Тест проверяет, что у каждого пункта `row/toggle/option/subsection` есть такой атрибут в исходниках страниц, а у каждого `path` — запись в `PAGES`.
- **Состояние** поиска — в `global.settingsSearch = { open, q }`, чтобы «назад» с целевой страницы вернул те же результаты. «Недавние» — `localStorage` (удобство на устройстве).
- **Клавиатура** лучше tweb: ↑/↓ двигают выделение, Enter открывает, Esc — очистить, затем закрыть.

## Приёмка

- Собеседник видит личный канал в профиле сразу после сохранения, с последним постом; клик открывает канал на этом посте; канал, ставший приватным, пропадает из профиля сам.
- В настройках любой пункт находится по началу слова, в любой раскладке и по синониму; переход открывает нужную страницу и подсвечивает строку; «назад» возвращает к результатам.
- Все тесты зелёные, строгий DOM — 0 нарушений, переходы без вспышек.
