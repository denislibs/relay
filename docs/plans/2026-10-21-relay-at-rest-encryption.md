# Защита переписки и файлов (без сквозного шифрования)

Ветка `feat/at-rest-encryption`. Цель: утечка любого одного компонента — дамп базы, бэкап, бакет S3, внутренняя
сеть, индекс поиска — не раскрывает переписку и файлы; удалённое перестаёт существовать; сеанс нельзя унести
вместе с профилем браузера.

Честно не обещаем: работающий сервер с доступом к KMS читает переписку (это не E2E); метаданные (кто, кому, когда,
размеры) видны; веб-клиент доверяет нашему серверу.

Принципы: никакой своей криптографии (WebCrypto: AES-256-GCM, HKDF, ECDSA P-256); шифр самоописываемый (версия
формата и ключа); каждый этап с переходным режимом (старое читается, новое пишется по-новому, задача догоняет);
dev без внешних сервисов (поддельный KMS).

## Этапы

| # | Что | Суть |
|---|---|---|
| 2 | Журнал по ссылкам | `newMessage`/`messageEdited` в `updates` — только `{chatId, id}`; `sync` подтягивает тела одним запросом и отдаёт прежний формат |
| 3 | Ядро криптографии | `crypto/`: `seal`/`open` (AES-256-GCM, AAD = строка+поле), интерфейс KMS (`FakeKms`, `VaultKms` — Transit), ключи чатов в `keys.chat_keys`, кэш ключей |
| 4 | Шифрование текста | `messages` (тело, разметка, подпись и прочее текстовое), `drafts`; запись и чтение во всех местах; задача перешифровки старых строк |
| 5 | Поиск | индекс Meilisearch изолирован (своя сеть, без бэкапа — восстанавливается из базы) |
| 6 | Удаление ключа | удаление чата удаляет ключ сразу; смена главного ключа перезаворачивает ключи чатов; схема `keys` бэкапится отдельно и коротко |
| 7 | Файлы | шифрование на клиенте кусками по 512 КБ (AES-GCM, nonce = база‖номер куска), ключ файла в сообщении; SW расшифровывает Range; worker видео расшифровывает во временный файл |
| 9 | Сервис ключей | доступ к KMS только у отдельного процесса; server/worker просят ключи по внутреннему каналу |
| 1 | TLS внутри | ssl к Postgres/Valkey/S3/Meilisearch из env; в production без TLS не стартуем |
| 8 | Сеанс на ключе устройства | при входе — неизвлекаемый ключ ECDSA P-256 в браузере; подключение WebSocket подписывает вызов сервера; одна cookie ничего не открывает |

## Решения этапа 0

- KMS: интерфейс + `FakeKms` (dev, тесты) + `VaultKms` (HashiCorp Vault / OpenBao, движок Transit). В compose —
  OpenBao в dev-режиме, чтобы настоящий путь тоже проверялся.
- Поиск: изолировать индекс сейчас, поиск на клиенте — как направление.
- Сроки: бэкапы данных — 30 дней, ключей — 7 дней.
- Аватарки, обои, музыка профиля не шифруются (публичные по смыслу).
